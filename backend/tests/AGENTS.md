# 测试脚本规范

本目录用于存放 SDK 的自动化测试脚本。测试目标是验证 SDK 模块代码是否符合预期,测试代码必须稳定、可复现、可独立执行，禁止为了通过测试而修改生产代码逻辑.

必须按照以下规范放置测试脚本代码文件，提前在 `/tests`包下创建好分类文件夹.规定如下:

- `backend`: 存在后端代码相关的测试.
- `frontend`: 存放前端代码相关的测试.

## backend测试
1. `backend/unit-test/*`: 存放验证最小可测试单元(例如函数、类、数据结构、配置解析器、状态转换逻辑), 不依赖真实数据库、Redis、外部模型、网络请求, 必须使用 fake/mock/stub 隔离外部依赖.

2. `backend/integ-test/*`: 用于验证多个 SDK 内部模块之间的协作, 例如: 配置加载 + 智能体实例组装创建, runtime 状态 + storage 适配器等.
可以使用本地临时文件、内存队列、SQLite、fake provider, 如必须依赖 PostgreSQL、Redis 等中间件，必须在测试 README 中写清楚启动条件和环境变量, 缺少依赖环境时，应明确 skip 或停止并说明原因，禁止伪造测试结果.

3. `backend/e2e-test/*`: 存放端到端测试脚本, 用于验证 SDK 在接近真实使用场景下的完整链路. 必须给出可复现的真实执行条件; 如果依赖真实模型、真实数据库、真实队列，必须通过环境变量配置; 禁止虚造模型响应、数据库结果、队列结果; 缺少执行环境时，停止任务并请求人类提供测试条件;

4. 所有测试目录必须配备 `Readme.md`, 内容必须简洁直白不废话, 人类阅读可直接按照步骤复现测试结果.

### 异步与事件测试规范
涉及异步事件、队列、任务通知、后台 Worker 的测试必须覆盖：
1. 事件成功发送;
2. 事件处理失败后的错误记录；
3. 事件重试逻辑；
4. 事件超时逻辑；
5. 并发任务不会阻塞用户对话主链路；
6. 后台任务异常不会中断主对话流程。
异步测试禁止依赖不确定的长时间 sleep，应使用可控的事件、超时、fake queue 或测试钩子
