# 评估表字段结构化覆盖检查

> 检查日期：2026-08-15  
> 来源目录：`docs/文档/评估表`  
> 检查对象：5份PDF原始评估表、现有结构化JSON、数据库业务设计文档

## 1. 检查结论

重新逐页核对后，原业务设计的主线能够支持问卷评估和人机协同，但原设计不能完整覆盖纸质表中的所有字段。

本次已在业务设计中补充以下结构：

| 新增结构 | 解决的问题 |
| --- | --- |
| `assessment_answer_option` | 单选、多选选项逐条结构化存储 |
| 选项附加文本、数值和单位 | “其他”、支/天、次/日、g/日等组合答案 |
| `assessment_action_definition` | 护理措施、通知医生、复查、宣教等模板配置 |
| `assessment_action_record` | 实际选择、推荐、通知和执行的措施 |
| `assessment_result_reference` | 入院评估单引用ADL、跌倒、压疮等独立量表结果 |
| `assessment_acknowledgement` | 跌倒、压疮高危告知及患者/家属确认 |
| `assessment_signature` | 护士、评定者、患者、家属等签名 |
| 评估上下文快照 | 姓名、年龄、科室、病区、床号、住院号、诊断 |
| 派生问题定义 | BMI、体重下降比例等计算字段 |

补充后，数据库业务设计可以覆盖这5份评估表的所有字段类型。仍需临床确认的内容属于评分规则问题，不是数据库字段容量问题。

## 2. 统一字段类型映射

| 纸质字段类型 | 结构化存储方式 |
| --- | --- |
| 患者姓名、性别、年龄、科室、病区、床号、住院号、诊断 | `patient`、`patient_encounter`，并在 `assessment_instance` 保存评估时快照 |
| 评估日期、时间 | `assessment_instance.assessed_at` |
| 单选题 | `assessment_answer` + 一条 `assessment_answer_option` |
| 多选题 | `assessment_answer` + 多条 `assessment_answer_option` |
| 文本填空 | `assessment_answer.answer_text` |
| 数字填空 | `assessment_answer.answer_number` + `answer_unit` |
| 是/否 | `assessment_answer.answer_boolean`，或选项明细 |
| 日期、时间 | `answer_date`、`answer_time`、`answer_datetime` |
| “其他”补充文本 | `assessment_answer_option.extra_text` |
| 带数量的选项 | `extra_number` + `extra_unit` |
| BMI、体重下降比例 | 派生问题 + `calculation_expression` + 系统计算答案 |
| 分项分、总分、风险等级 | `assessment_score` |
| 其他量表评分引用 | `assessment_result_reference` |
| 通知医生、复查、护理措施、住院告知 | `assessment_action_definition` + `assessment_action_record` |
| 风险告知 | `assessment_acknowledgement` |
| 护士、患者、家属、评定者签名 | `assessment_signature` |
| 纸面多列复评 | 每个日期/时间创建独立 `assessment_instance` |

## 3. NRS2002营养风险筛查表

### 字段覆盖

| 表单内容 | 数据类型 | 数据库存储 |
| --- | --- | --- |
| 科室、姓名、年龄、性别、床号、住院号、入院时间、诊断 | 公共上下文 | 患者、住院记录及评估快照 |
| 身高、体重 | 数字+单位 | 评估问题与数字答案 |
| BMI | 派生数字 | 由身高体重计算后保存 |
| 卧床 | 布尔 | 布尔答案 |
| 初步筛查4个问题 | 是/否 | 问题、选项和答案选项明细 |
| 疾病严重程度评分 | 单选评分 | 问题、评分选项、临床分值 |
| 营养状态受损评分 | 单选评分 | 问题、评分选项、临床分值 |
| 原体重、现体重、体重减轻百分比 | 数字及派生值 | 数字答案、计算答案 |
| 年龄加分 | 规则计算 | 评估规则和评分结果 |
| 总分 | 临床得分 | `assessment_score` |
| 营养支持、每周复查 | 处置规则 | 动作定义与动作记录 |
| 筛查者签名、筛查时间 | 签名与时间 | `assessment_signature`、`assessed_at` |

覆盖结论：可完整结构化。

待确认规则：

- 疾病严重程度的疾病选项是否允许多选，最终取最高分还是人工确认分值。
- 总分小于3分且将接受重大手术时，“每周复查”是否自动生成后续任务。

## 5. 入院评估单

### 基本情况

| 表单内容 | 数据类型 | 数据库存储 |
| --- | --- | --- |
| 性别、年龄、职业 | 文本/数字 | 评估问题和答案 |
| 婚姻、宗教、教育程度 | 单选 | 答案选项明细 |
| 资料来源、入院方式、陪同人、日常照顾者 | 多选 | 多条答案选项明细 |
| “其他”说明 | 选项附加文本 | `extra_text` |
| 诊断 | 长文本 | 评估快照和文本答案 |

### 护理评估

| 表单内容 | 数据类型 | 数据库存储 |
| --- | --- | --- |
| 体温、脉搏、呼吸 | 数字+单位 | 数字答案 |
| 血压 | 两个数字 | 收缩压、舒张压两个独立问题 |
| 身高、体重 | 数字+单位 | 数字答案 |
| BMI | 派生数字 | 计算问题和计算答案 |
| 过敏史、药物依赖 | 是/否+详情 | 布尔答案和补充文本 |
| 既往史、饮食、口腔、睡眠、皮肤等 | 单选/多选 | 答案及选项明细 |
| 呼之能应、对答切题 | 分组选择 | 独立问题或同一分组下的子问题 |
| 大便、小便异常 | 多选+次数 | 选项明细、附加数值和单位 |
| 偏瘫部位 | 多选 | 每个肢体方向独立选项 |
| 吸烟、饮酒 | 是/否+数量 | 选项明细、附加数值和单位 |

### 量表结果与护理动作

| 表单内容 | 数据类型 | 数据库存储 |
| --- | --- | --- |
| ADL、跌倒、压疮、疼痛、营养、误吸风险评分 | 关联量表结果 | `assessment_result_reference` |
| 是否满足通知医生条件 | 规则结果 | 引用记录中的条件命中标识 |
| 是否通知医生 | 业务动作 | `assessment_action_record` |
| 基础护理、专科护理、患者安全 | 多项护理措施 | 动作定义与动作记录 |
| 护理交接班重点 | 多项措施 | 动作定义与动作记录 |
| 提醒患者及家属关注 | 宣教动作 | 动作定义与动作记录 |
| 住院告知 | 完成项 | 动作定义与动作记录 |
| 记录时间、责任护士签名 | 时间与签名 | `assessed_at`、`assessment_signature` |

覆盖结论：增加答案选项明细、结果引用、动作记录和签名后可完整结构化。

待确认规则：

- 部分复选框在实际业务中可能要求单选，需要护理人员逐项确认。
- 疼痛、MNA-SF、STRONkids、SSA量表原件目前不在评估表目录，暂时只能保存外部结果引用或人工录入结果。

## 8. 数据库设计仍需调整的原则

| 原则 | 说明 |
| --- | --- |
| 不以JSON代替核心关系 | 复选项、护理措施、签名、量表引用必须有明细表 |
| 保留快照 | 题目、选项、分值、患者基本信息和告知文字都应保留当时快照 |
| 一次复评一条实例 | 不按纸面横向列设计数据库字段 |
| 临床结果与动作分离 | 量表分数保存在评分表，通知医生和护理措施保存在动作记录 |
| 原始回答与结构化答案分离 | 对话原文在消息表，结构化答案在评估答案表 |
| 签名和告知分离 | 签名记录身份和时间，告知记录当时展示的内容及确认结果 |

## 9. 最终判断

当前业务设计经过本次补充后，可以覆盖5份量表的全部字段类型，并能够做到结构化存储、重复评估、评分追溯、措施查询、签名确认和科研对比。

仍未解决的是部分量表的临床计分规则和风险等级阈值。这些内容需要护理团队确认后配置到 `assessment_rule`，不需要再次修改数据库结构。
