# 实时语音评估结束流程修复计划

## 需求目标

修复患者端实时语音评估结束时的两个问题：

1. 服务端关闭语音会话或页面退出时，浏览器必须停止麦克风采集、关闭实时语音连接，并提供明确的“关闭语音”操作。
2. 评估结构化答案达到完整后，不得立即替换患者端输入区域或打断最后一条 AI 回复；必须等待最新 Qwen Realtime 响应完成、浏览器端音频队列播放完毕，再显示任务结束提示并关闭语音与输入控件。

纯文本对话链路保持现有行为，不改变其 Dialog Agent、SSE 和任务结束流程。

## 现状与约束

- 患者端实时语音通过 WebSocket 连接 `/api/ws/dialog/{session_no}/voice`，后端 `VoiceGateway` 托管 Qwen Realtime 上游。
- 患者转写、AI 文本、工具事件、音频索引和任务状态继续写入现有 `dialog_stream:{session_id}`，SSE 仍负责断线续读。
- Extraction Agent 与 Voice Gateway 运行在不同进程，不能依赖进程内变量传递“评估完成”和“模型响应完成”状态，必须使用 Redis 持久化短期状态并保证幂等。
- 浏览器端实时 PCM 音频由 `Pcm16AudioPlayer` 排队播放；模型 `response.done` 只表示上游生成完成，不等于浏览器已经播放完毕。
