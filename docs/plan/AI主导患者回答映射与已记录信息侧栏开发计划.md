# AI 主导患者回答映射与已记录信息侧栏开发计划

> 基线：`e7e77e8d5ec85f1b87063fb3804c03352f0485df`
> 分支：`refactor/extraction-ai-answer-mapping`

## 1. 需求与边界

- [X] 1.1 患者自然语言到量表题目的语义归属由 Extraction AI 决定。
- [X] 1.2 AI 无法明确对应题目时返回空答案，不由后端根据问句关联、关键词或题目顺序猜测。
- [X] 1.3 AI 直接输出最终结构化答案：题目 ID、答案类型、答案值或选项编码、证据与置信度。
- [X] 1.4 后端只负责结构合法性、题目归属、选项编码、数据类型和置信度边界校验，再持久化。
- [X] 1.5 `related_question_id` 仅可作为诊断/目标提示信息，不再作为答案归属事实来源，也不得因其为空导致 Dialog 任务失败。
- [X] 1.6 BMI、体重下降比例、量表计分等确定性计算继续由后端执行。
- [X] 1.7 不引入三候选、冷却、`report_question_choice` 强制门禁、think 过滤或新的护士通知逻辑。

## 2. Extraction AI 契约

- [X] 2.1 先写失败测试：选择题要求模型直接返回真实 `option_code`，后端不再根据中文标签或值二次猜测。
- [X] 2.2 先写失败测试：布尔、数值、日期、文本均使用模型给出的最终结构化值，后端仅校验类型。
- [X] 2.3 先写失败测试：AI 返回未知题号、无效选项或类型不符时只丢弃该候选，不影响同批其他有效答案。
- [X] 2.4 先写失败测试：无法判断对应题目时允许 `answers=[]`，不得触发人工介入或后端猜测。
- [X] 2.5 修改结构化输出模型、提示词和转换逻辑。

## 3. Dialog 对题号关联解耦

- [X] 3.1 先写失败测试：上一条 AI 消息 `related_question_id=None` 时，处理患者回答不得抛出 `AI 问句未关联有效量表问题`。
- [X] 3.2 下一问以当前有效结构化答案的缺失题为事实来源，不依赖上一条 AI 消息题号决定进度。
- [X] 3.3 Redis 状态缺失、历史 AI 消息无题号关联时也能恢复并继续对话。
- [X] 3.4 保留已有 AI 消息题号时仅作为诊断信息，不作为 Extraction 答案映射依据。
