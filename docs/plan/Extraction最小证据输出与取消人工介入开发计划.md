# Extraction 最小证据输出与取消人工介入开发计划

## 目标

将 Extraction Agent 改为最小职责：只判断患者本轮内容能够填写哪些量表题目，并为每个候选答案返回题目 ID、答案值、患者原话依据和置信度。题目编码、答案类型、来源消息、选项定义、临床得分等确定性信息全部由后端根据题目 ID 和当前消息补齐。

有效答案继续写入现有 `assessment_submission`、`assessment_answer` 和选项明细，并直接展示在护士端结构化答案表中。Extraction 解析失败不再自动产生人工介入或护士全局提醒。

本计划只取消 **Extraction 解析失败自动产生的人工介入和护士提醒**。患者主动呼叫、历史呼叫事件和其他业务产生的人工介入暂不删除。

## 1. 需求与现状确认

- [X] 1.1 确认当前模型重复生成题目编码、答案类型、来源消息、临床得分和调试说明，增加了不必要的格式失败点。
- [X] 1.2 确认模型只需要判断哪些题目已有明确答案，并提供答案值及患者原话依据。
- [X] 1.3 确认题目 ID 是模型输出与后端量表定义之间的唯一关联键。
- [X] 1.4 确认题目编码、答案类型、来源消息和临床得分由后端补齐或计算。
- [X] 1.5 确认单个候选答案无效时不得升级为护士紧急呼叫。

## 2. 最小模型输出契约

- [X] 2.1 定义最小候选答案 Schema：

  ```json
  {
    "answers": [
      {
        "question_id": 123,
        "value": "腹泻3-4次/日",
        "evidence": "患者说：我一天大概拉三四次",
        "confidence": 0.93
      }
    ]
  }
  ```

- [X] 2.2 `value` 只允许字符串、数字、布尔值或字符串数组；日期使用 ISO 日期字符串，选择题可返回选项编码、标签或值，由后端结合当前题目做唯一映射。
- [X] 2.3 `evidence` 必须是患者本轮或历史对话中的明确原话依据，不输出隐藏推理过程。
- [X] 2.4 无法确认任何题目时返回空 `answers`，禁止猜测或生成“待人工确认”伪答案。
- [X] 2.5 为最小 Schema、空结果、单题结果、多题结果和错误值类型补充单元测试。

## 3. 后端题目映射与答案规范化

- [X] 3.1 使用 `question_id` 从当前任务绑定的已发布量表版本中加载真实题目定义。
- [X] 3.2 拒绝不属于当前任务量表的问题 ID，但只记录诊断日志，不触发人工介入。
- [X] 3.3 从题目定义取得真实 `question_code` 和 `answer_type`，模型不再返回这两个字段。
- [X] 3.4 按真实答案类型规范化 `value`：文本、数字、布尔、日期、单选和多选分别校验。
- [X] 3.5 单选和多选在当前题目范围内将选项编码、标签或值唯一映射为真实 `option_code`；无法唯一映射时保留题目未完成，等待后续澄清。
- [X] 3.6 使用当前患者消息编号补齐 `source_message_ids`，不要求模型重复返回消息编号。
- [ ] 3.7 将 `evidence` 保存为解析审计依据或事件展示字段，不把它当作临床答案值。
- [X] 3.8 临床得分只使用数据库量表选项和计分规则计算，模型不再返回 `clinical_score`。

## 4. Extraction 提示词与运行器改造

- [X] 4.1 更新提示词，只要求识别可填写题目、答案值、原话依据和置信度。
- [ ] 4.2 明确当前 AI 问句优先，允许患者一轮明确回答多个题目，但禁止把同一句短回答复制给无关题目。
- [ ] 4.3 保留历史结构化答案和必要的对话摘要，用于识别补充与更正；模型输出仍采用同一最小 Schema。
- [X] 4.4 Runner 将候选答案转换为现有 `ExtractedAnswer` 内部对象后再交给结果写入器，避免扩大数据库改动。
- [X] 4.5 单个候选转换失败时跳过该候选并记录原因，其他有效候选继续落库。

## 5. 取消 Extraction 自动人工介入

- [X] 5.1 删除候选答案无效时触发 `_mark_manual_intervention` 和 `_publish_manual_alert` 的路径。
- [X] 5.2 Extraction 候选无效只记录结构化诊断信息，不创建 `handoff_requested` 事件。
- [X] 5.3 Celery 请求级失败保留后台重试；达到重试上限后记录失败状态和日志，不伪装成 AI 工具呼叫护士。
- [X] 5.4 Extraction 不再设置 `care_task.need_manual_intervention`、`intervention_reason`、`interaction_session.handoff_required` 和 `handoff_reason`。
- [ ] 5.5 保留历史人工介入事件的只读兼容，不删除既有呼叫记录。

## 约束

- 模型只负责 `question_id`、`value`、`evidence` 和 `confidence`，不重复生成数据库已有元数据。
- 数据库中的题目编码、答案类型、来源消息和临床得分以当前任务绑定的量表版本为唯一事实来源。
- 不因单个候选格式错误呼叫护士，不把 Extraction 内部异常转换成 `handoff_requested`。
- 不把低置信度候选自动视为护士最终确认结果；护士端展示的仍是 `ai_extraction` 提交。
- 不修改或删除现有患者主动呼叫及历史呼叫事件。
