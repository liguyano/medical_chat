# 继续对话读取已记录答案并跳题开发计划

## 目标

患者继续或恢复 AI 对话时，以 PostgreSQL 中当前会话的有效结构化答案为事实来源：已经记录且有效的题目不再重复询问；空值、低置信度、无效候选和“待人工确认”题目仍保持未完成并允许后续澄清。实时语音连接重新建立后也必须恢复该进度，不能仅向语音模型重新发送完整量表。

## 1. 需求与边界确认

- [X] 1.1 有效答案沿用 `valid_assessment_answer_condition()`：存在真实值或有效选项，且 AI 抽取置信度不低于 `0.6`。
- [X] 1.2 “待人工确认”、空值、无法映射选项和低置信度答案不视为完成。
- [X] 1.3 派生题不参与直接提问，继续沿用必填、非派生题进度规则。
- [X] 1.4 本次同时覆盖实时语音恢复和文本 Dialog 下一题选择，不修改量表答案落库结构。

## 约束

- PostgreSQL 结构化答案是是否跳题的唯一事实来源；Redis Schedule 状态和“曾经问过”记录不能代替有效答案。
- 不删除患者历史消息和旧答案，不自动修改低置信度答案。
- 不等待当前轮 Extraction 才允许语音响应；同一上游连接依靠对话历史衔接，下一轮开始前再同步最新持久化进度。
