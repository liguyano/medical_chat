# 任务创建时生成话题路线

用户确认试做：创建任务时把所选问题串成生活话题路线；对话按路线自然展开，可根据患者回答跳转，已有明确答案不重问。main与备份不动，不推送。

## 1、路线生成与持久化
- [X] 1.1 增加话题结构与覆盖校验的失败测试：全部必填编码覆盖一次，拒绝未知/重复/遗漏编码。
- [X] 1.2 Schedule prepare同次模型调用生成topic_route，含入口、展开、不同回答分支、证据不足规则与下一话题连接。
- [X] 1.3 路线随Task-todo写Redis，并通过现有任务准备JSON快照保存；缓存过期时从快照恢复，不每轮重生成。

## 2、真实运行入口
- [X] 2.1 路线按当前有效剩余题过滤，完成的话题跳过；路线走完不能代替数据库完成判断。
- [X] 2.2 文字首问/每轮规划/生成和真实语音建连/结束校正都注入同一任务路线，避免仅文字模拟生效。
- [X] 2.3 旧任务无路线时保留既有方式，不强制修改已有任务；新建任务使用新版路线。

## 3、验证交付
- [ ] 3.1 全部单元、静态检查及合成路线生成与消费验证；真实模型只用已授权的同一服务和虚构内容。
- [X] 3.2 独立审查，记录实际语音验证边界，不把文本模拟算作语音通过。
- [X] 3.3 真实语音行为断言未通过，保留试验分支，不合并dev/main、不推送；保留用户原文件及上次诊断文档，不重启用户服务。

设计：SDK只负责路线模型/校验/筛选和提示渲染，app负责现有数据库快照与Redis恢复。评分、题目原义、固定施测、模糊回应规则及完成工具不变。不增加互相指挥的新智能体。

验证结果：373项单元与静态检查通过，真实路线生成通过；真实语音行为断言失败（复合追问、通话确认追加问题），3.1效果验收保持未完成。详情见同日审查记录。
