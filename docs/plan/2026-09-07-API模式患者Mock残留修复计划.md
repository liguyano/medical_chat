# API 模式患者 Mock 残留修复计划

## 目标

修复 API 模式下真实任务 ID 与前端 Mock 任务 ID 相同时，患者对话页错误展示 Mock 患者已完成会话的问题。API 请求失败时只能展示加载错误，不得展示 Mock 或其他患者的残留数据。

## 约束

- Mock 模式继续保留现有演示数据和交互能力。
- API 模式的任务、会话、结构化答案和领域事件初始状态必须为空。
- API 对话快照加载前必须清除当前任务对应的旧会话状态。
- 不修改后端接口、DTO、SSE 或 WebSocket 协议。
- 使用 Vitest 先建立失败用例，再实施最小修复。

## 1. 建立回归测试

- [ ] 1.1 增加 API 模式 Store 初始化测试，验证任务和对话状态不包含 Mock 数据。
- [ ] 1.2 运行定向测试，确认用例因当前无条件注入 Mock 数据而失败。
- [ ] 1.3 增加当前任务会话清理测试，验证会话、结构化答案和领域状态均被删除。
- [ ] 1.4 运行定向测试，确认现有局部清理行为无法满足快照加载隔离要求。

## 2. 隔离 Mock 与 API 初始状态

- [ ] 2.1 根据 `runtimeConfig.dataMode` 构造任务 Store 初始状态：Mock 模式注入演示任务，API 模式使用空数组。
- [ ] 2.2 根据 `runtimeConfig.dataMode` 构造对话 Store 初始状态：Mock 模式注入演示会话、答案和事件，API 模式使用空对象。
- [ ] 2.3 保持 `resetDemoData` 仅显式恢复演示数据，避免改变现有 Mock 演示入口语义。
- [ ] 2.4 运行 Store 定向测试并确认通过。

## 3. 修复患者对话快照加载边界

- [ ] 3.1 API 快照请求开始前清除当前任务完整会话状态，而不是只清除领域卡片。
- [ ] 3.2 增加明确的快照加载状态；加载期间不以旧会话计算完成态或渲染旧患者对话。
- [ ] 3.3 快照请求失败时保留空会话并展示现有错误提示，不回退 Mock 数据。
- [ ] 3.4 运行对话恢复和患者页面相关测试并确认通过。

## 4. 验证与审查

- [ ] 4.1 运行 `pnpm test`。
- [ ] 4.2 运行 `pnpm lint` 和 `pnpm typecheck`。
- [ ] 4.3 使用真实浏览器验证桌面端与 390px 患者端；确认任务 ID `3` 加载期间不显示王秀英或 `15/15`。
- [ ] 4.4 检查浏览器控制台无错误，并记录无法完成的环境验证项。
- [ ] 4.5 审查变更范围、更新本计划勾选状态，并按中文 Git 规范提交。
- [ ] 4.6 检查并停止本任务启动的前后端进程；不停止用户原有进程。
