# 字段抽取类型统一与人工介入修复计划

## 目标

修复 Extraction Agent 因答案类型命名不统一导致的批次失败、重复重试和评估进度卡住问题；保留简洁对话摘要，增加单字段容错和达到重试上限后的医护人工介入；患者端与医护端持续展示已记录字段（包括无效值），便于人工修正。

## 开发步骤

- [X] 1. 统一答案类型契约
  - [X] 1.1 盘点原始量表、数据库、Agent Schema、前后端契约中的答案类型
  - [X] 1.2 统一为 `text`、`number`、`boolean`、`date`、`single_choice`、`multiple_choice`
  - [X] 1.3 清理历史多选别名、中文答案类型及相关硬编码
  - [X] 1.4 修正量表目录导入和运行时问题类型映射

- [X] 2. 改造增量抽取上下文
  - [X] 2.1 保留“全部目标字段 + 历史结构化字段 + 对话摘要 + 当前对话”结构
  - [X] 2.2 历史结构化字段只传模型识别出的有效字段值，保留选择题选项值
  - [X] 2.3 摘要改为简洁事实和矛盾点，排除当前消息重复内容
  - [X] 2.4 增加上下文构造测试

- [X] 3. 防止单字段错误污染批次
  - [X] 3.1 对模型原始结构化结果逐条校验
  - [X] 3.2 丢弃无效字段并保留有效字段
  - [X] 3.3 仅对真正的请求级/批次级错误重试
  - [X] 3.4 达到重试上限后停止当前批次，发布人工介入事件

- [X] 4. 医护端人工介入闭环
  - [X] 4.1 后端保存 Extraction Agent 最终失败状态和待人工字段
  - [X] 4.2 提供医护查询、修改和确认字段值接口
  - [X] 4.3 医护端展示失败原因、待处理字段和人工处理状态
  - [X] 4.4 患者端展示人工介入提示但不自动重跑历史消息

- [X] 5. 字段展示与进度修复
  - [X] 5.1 前后端持续展示有效值、无效值和空值
  - [X] 5.2 进度只按有效答案计算，字段列表不丢失无效答案
  - [X] 5.3 修复前端 `null` 值展示和计数问题

- [X] 6. 测试与交付
  - [X] 6.1 后端类型、上下文、容错、重试和人工介入测试
  - [X] 6.2 前端字段展示、失败状态和医护编辑测试
  - [X] 6.3 运行前后端测试、静态检查和任务101只读验证
  - [X] 6.4 更新审查文档并合并回本地 `main`

## 约束

- 不自动重新执行任务 101 的历史抽取；修复后仅由患者在原对话发送新消息触发新的抽取任务。
- 不保留错误答案类型的兼容解析或历史别名。
- 不限制模型正常发起多次工具调用。
