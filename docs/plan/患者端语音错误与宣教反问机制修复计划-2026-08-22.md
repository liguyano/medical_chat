# 患者端语音错误与宣教反问机制修复计划（2026-08-22）

## 目标

在不改变患者端身份证号 + 手机号登录契约、`/api`、SSE、WebSocket 路径和既有工具 DTO
的前提下，修复实时语音竞态导致的会话卡死，改善患者称呼与沟通情感，并为医学宣教增加
可验证的 teach-back 反问闭环。

## 计划

1. 需求与现状确认
   - [X] 复现并定位 `Conversation has no active response` 的上游触发路径
   - [X] 核对文本/语音共用 Dialog 提示词、工具事件和宣教状态现状
   - [X] 确认不改变登录、SSE、WebSocket 和既有工具接口契约
2. 实时语音竞态修复
   - [X] 为 Voice Gateway 增加响应创建的串行/幂等状态保护
   - [X] 处理工具调用、连续快速停顿和打断后的重复 `response.create`
   - [X] 对可恢复的“无活动响应”供应商错误恢复监听状态，不切换为文字并卡死会话
   - [X] 增加工具调用、快速多轮和竞态错误回归测试
3. 患者称呼与沟通提示词
   - [X] 增加性别/年龄/患者偏好驱动的礼貌昵称规则
   - [X] 禁止每轮直接念完整姓名，保留开场身份核实和自然称呼
   - [X] 增加温暖、耐心、有变化的回应示例和测试断言
4. 宣教 teach-back 闭环
   - [X] 在 Dialog 提示词中加入宣教后反问、患者复述和理解判断规则
   - [X] 将宣教未完成/待复述规则注入 Dialog 与 Schedule 后续轮次提示词
   - [X] 理解失败时重新解释，理解成功后才允许标记宣教完成并回到评估
   - [X] 覆盖文本和实时语音共用的提示词测试
5. 验证与交付
   - [X] 运行后端相关单测、前端检查和构建
   - [X] 使用李国强身份浏览器复查连续语音、工具宣教和文字回退
   - [X] 更新 `docs/review` 记录原因、修复和无法由代码伪造的外部依赖
   - [X] 停止前后端调试进程，合并功能分支回 `main`

## 风险与边界

- Qwen Realtime 的具体事件时序由供应商连接决定，后端只能通过本地状态机、幂等锁和
  可恢复错误处理保证会话不被前端卡死，不能伪造供应商模型能力。
- “患者是否理解宣教”由模型依据患者复述判断；若患者表达含糊、拒绝复述或模型服务
  不可用，必须继续解释或转护士，不能把未确认状态标记为已完成。
