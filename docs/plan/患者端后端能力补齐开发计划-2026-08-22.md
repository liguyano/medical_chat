# 患者端后端能力补齐开发计划（2026-08-22）

## 目标

在不破坏既有医护端、患者端 API 及生产传输路径的前提下，补齐患者端 UI 原型依赖的真实后端能力，并让前端 API 模式使用真实数据。数据库模型、迁移和接口字段以 `docs/sql/数据库表业务设计.md` 与 `docs/sql/出入院宣教与知情同意数据库设计补充.md` 为唯一事实来源。

## API 影响清单

- 保留：`POST /api/patients/login`（完整身份证号 + 手机号）、现有患者任务/评估/对话接口、`/api/ws/dialog/{session_no}/voice`。
- 新增：`POST /api/patients/verify-task`、`POST /api/patients/scan/verify`、`GET /api/patient-notifications`、`POST /api/patient-notifications/{id}/read`、`GET /api/patient-ward-guide`、`POST/GET /api/patient-assistant/*`、`GET/POST /api/consent-forms/{task_ref}/snapshot|playback|clauses|sign`。
- WebSocket 新增控制/事件：`transcript_ready`、`confirm_transcript`、`retry_transcript`；旧控制消息保持兼容。

## 需外部系统提供的内容

- 生产扫码令牌由医院二维码/门禁系统生成；未配置时接口返回明确的 `unavailable`，不生成演示患者数据。
- 病区指南、快捷问题和助手知识由病区配置或知识库提供；没有配置时只返回安全的转护士提示。
- 知情同意音频由审核后的音频服务提供；后端只保存受保护的相对地址和播放事件。
