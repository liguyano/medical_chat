# 对话评估完整流程 - 第一期文本闭环

**需求范围**：医护端选患者 → 查真实量表 → 发任务（collection_mode=ai_dialogue）→ Schedule/Dialog/Extraction 三智能体后台协作 → 患者多轮文本对话 → 字段抽取 → 护士实时监控（全程 SSE），`NEXT_PUBLIC_DATA_MODE=api`。

**明确约束**：
1. **前后端职责分工（GOVERNING）**："你不需要写前端代码，只需要写后端代码，然后把API接口文档写好就可以了，前端我会另外安排。" — 本计划**仅实现后端**，不编辑 frontend/* 文件。
2. **问诊语义（GOVERNING，不得违背）**：AI 扮演医护人员主导问诊。AI **先问**（从 Task-todo 量表问题列表开始），患者答，AI 根据答案 + Task-todo + Schedule 约束 + 关键词产出**下一个问诊问题**。"AI 输出" = 下一个问诊问题，**不是**对患者输入的回复。开场白（opening）= AI 的**第一个问诊问题**，发生在任何患者输入之前。
3. **实现要求**："先按照这个方案开干吧... 前后端整体都完成，不准偷懒实现最小MVP。" — 后端必须**完整实现**本计划，不能偷懒搞最小 MVP。
4. **第一期范围**：文本引擎 only；会话状态绑定 Redis（不做进程绑定）；接通真实 execute_tool；不做语音全双工/暂停/恢复/人工介入/评分/知情同意/质量评价/传统问卷流程；不写测试脚本（其他人测试）。

## 8. SSE 事件契约对齐（任务 #28）

### 8.1 前端预期事件名称（READ ONLY）

前端 `sseClient.ts` 定义的 `SseEventType`：
- `session_snapshot` / `session_status`
- `user_transcript_delta` / `user_transcript_completed`（患者输入）
- `assistant_message_started` / `assistant_text_delta` / `assistant_audio_delta` / `assistant_message_completed`（AI 问诊问题）
- `extraction_updated`（字段抽取结果）
- `progress_updated`（进度/约束/工具调用）
- `education_triggered` / `education_status_updated`（宣教触发，第一期不涉及）
- `consent_triggered`（知情同意触发，第一期不涉及）
- `handoff_requested` / `handoff_resolved`（人工介入，第一期不涉及）
- `task_status_updated`（任务状态变更）
- `error` / `heartbeat`

前端 `applyRealtimeEvent.ts` 根据 `event_type` 幂等更新 Zustand Store，核心字段：
- `event_id` (SSE id)
- `event_type` (SseEventType)
- `task_id` (必需，用于路由到 Store session)
- `session_id` (可选)
- `message_id` (可选)
- `occurred_at` (ISO 8601 时间戳)
- `payload` (dict，包含具体字段，如 `content_text` / `delta` / `turn_no` / `cicare_stage` / `question_id` / `fields` / `confidence_scores`)

### 8.2 后端当前映射（MODIFY）

`app/services/sse_service.py` 的 `_EVENT_NAME_MAP` 将 SDK 事件类型映射为 SSE event 名称：

**问题**：后端映射名称（`dialog_message` / `progress_update`）与前端预期不完全一致。

### 8.3 对齐方案（任务 #28）

**原则**：第一期最小可用，只对齐核心事件，非核心事件后补。

#### 8.3.1 核心事件对齐（必做）

| 后端 SDK 事件类型 | 当前映射 | 修改为 | 前端消费逻辑 | 优先级 |
|---|---|---|---|---|
| `DIALOG_TURN` | `dialog_message` | `assistant_text_delta` | `appendDelta(role='ai')` | P0（AI 问诊问题流式输出） |
| `PATIENT_ANSWER` | 无映射 | `user_transcript_completed` | `appendMessage(role='user')` | P0（患者答案完整消息） |
| `EXTRACTION_RESULT` | `progress_update` | `extraction_updated` | `updateFields(fields+confidence)` | P0（字段抽取结果） |
| `TOOL_CALL` | `progress_update` | `progress_updated` | 保留，`pushEvent` | P1（工具调用进度） |
| `CONSTRAINT` | `progress_update` | `progress_updated` | 保留，`pushEvent` | P1（约束触发） |
| `SESSION_END` | `progress_update` | `task_status_updated` | `updateTaskStatus` | P1（会话结束） |

#### 8.3.2 非核心事件（第一期不处理，后补）

- `session_snapshot` / `session_status` — 第一期前端从 GET /api/dialog/{session_no}/history 获取初始状态
- `assistant_message_started` / `assistant_message_completed` — 第一期无流式分段标记
- `assistant_audio_delta` — 第一期无语音
- `education_triggered` / `consent_triggered` / `handoff_requested` — 第一期无宣教/知情同意/人工介入

### 9.1 文档结构

文档保存路径：`docs/API接口文档-第一期文本闭环.md`

章节：
1. 概述（项目背景、技术栈、认证方式）

### 9.2 核心要点

- **响应格式**：所有 HTTP 端点返回**裸 payload**（不包含 `{code, message, data}` 外壳），`httpClient.ts` 直接返回 `payload as T`。
- **SSE 信封格式**：
  ```
  event: <event_name>
  id: <redis_stream_message_id>
  data: <json_payload>
  ```
- **错误处理**：HTTP 错误通过标准状态码返回，SSE 错误通过 `event: error` + `data: {message: "..."}` 返回。
