## 2. Worker 生命周期修复

- [X] 2.1 Celery Worker 进程常驻，Dialog、Schedule、Extraction Agent 按轮创建并在任务结束后释放。
- [X] 2.2 创建任务时只派发预热和 Dialog 首问任务。
- [X] 2.3 患者答案落库后按 `Schedule -> (Dialog + Extraction)` 派发单轮任务。
- [X] 2.4 为三个 Agent 增加按消息维度的 Redis 租约和已处理状态，避免重复消费。
- [X] 2.5 Redis 状态缺失时从 PostgreSQL 对话历史恢复当前题目和轮次。

## 3. 模型输出恢复

- [X] 3.1 模型开始生成时发布 `assistant_message_started`。
- [X] 3.2 模型生成期间向 Redis Stream 追加 `assistant_text_delta`。
- [X] 3.3 使用 `dialog:output:{session_id}:{message_id}` 保存完整文本快照。
- [X] 3.4 模型完成后标记 `completed`，保存 AI 完整消息到 PostgreSQL 并发布完成事件。
- [X] 3.5 模型失败后标记 `failed`，发布错误事件并交给 Celery 重试。
- [X] 3.6 SSE 首次连接和断线重连时先返回最新快照，再从快照游标继续消费增量。
