# 实时语音提前结束恢复方案

## 基线

- 开发基线：`fix/qwen-structured-thinking@de269ab`
- 功能分支：`fix/voice-premature-close-recovery`
- 基线差异：该稳定版本尚未引入后续分支中的 `dialog_question_service / report_question_choice` 候选题门禁，因此恢复选题直接使用“Schedule Task-todo 顺序 ∩ 结构化 remaining_question_ids”，一次只选择一题。

## 目标

Qwen Realtime 已经把一轮语音完整播给患者后，如果回复明确宣告“评估完成/结束”，系统再做事后核验。若当前患者回答尚在 Extraction Agent 处理中，先异步等待该消息被处理；处理完成后以结构化评估进度为唯一事实来源。未完成则自动纠正并补问一题，已完成则维持现有结束流程。

该方案不做输出前审核，不增加实时音频首包延迟。

## 设计边界

- [X] 评估是否完成只相信 `assessment_progress_service` 的有效结构化答案。
- [X] 结束语检测只判断 AI 回复有没有明确的结束意图，不判断业务是否完成。
- [X] 单独“谢谢/感谢配合”不视为结束，降低误判。
- [X] 同一个 Qwen Realtime 连接继续保留原 conversation history。
- [X] 恢复轮重新构建 instructions，只暴露当前一条未完成题，不重新下发整张后续问题表。
- [X] 真正 SessionEnd 仍走原有“Extraction 完成 + 可见 response.done”完成屏障。
- [X] 患者重新开口优先：取消未执行的恢复任务/恢复响应并还原长期提示词。
- [X] 恢复响应本身不再次进入提前结束检测，避免递归恢复。

## 后续可选增强

第一版为了便于调试，结束意图检测采用确定性规则。若真实联调发现模型会使用大量无法覆盖的隐式结束表达，可以把 `VoiceTurnGuard.has_closing_intent()` 换成“规则初筛 + 小模型二分类”；结构化完成判断、Extraction 等待和下一题恢复链路无需改变。
