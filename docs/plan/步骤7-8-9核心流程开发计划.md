## 范围与约束（已与用户确认）

1. **技术决策**：批次 A 不做鉴权；音频用 Base64 传输；SSE 心跳 30 秒 ping；关键词精确匹配 + 简单正则；不做"护士接管对话"功能。
2. **路由前缀**：不做版本控制（无 `/api/v1/`），直接使用语义化前缀。
3. **统一错误码**：建立 `ERR_XXX_NNN` 错误码体系。
4. **实现顺序**：本次只实现核心流程 = 任务创建 + 对话交互 + SSE，其余 API（抽取结果确认、护士评分、宣教/知情同意）后续补充。
5. **测试策略**：测试由独立 `test/*` 分支负责；本次只产出**测试计划文档**，不写、不跑测试代码。
6. **医护端监听**：`GET /api/sse/monitor/{session_no}` 本次做单会话只读监听（复用 `dialog_stream`）；多会话聚合后补。
7. **AI 回复驱动**：`POST /api/dialog/message` 仅落库 + 发 `DialogTurnEvent`；AI 回复由已有 Dialog Agent（Celery worker）异步产出，经 `dialog_stream` 走 SSE 回推。API 不同步调模型。

**开发顺序**：步骤9（FastAPI 骨架 + 核心 API）→ 步骤8（SSE）→ 步骤7（字典库拦截）。
理由：SSE 与拦截器都依赖 FastAPI 应用骨架先就绪。

## 已确认的代码现状（关键前置）

- `app/main.py` **为空**，FastAPI 应用尚未初始化。

- `app/models/base.py` 提供同步 `init_db(database_url)`、`get_db()`（同步 Session）。

- 领域锚点：任务创建落 `care_task`；对话落 `interaction_session` / `interaction_message`；
  步骤7 关键词规则来源为 `interaction_rule` 表。
- 事件发布：`DialogEventPublisher.publish()` → `dialog_stream:{session_id}`（已实现）。

- [X] 事件类型映射：`dialog_message` / `progress_update` / `error`
