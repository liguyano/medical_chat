# 桌面对话进度与候选题冷却开发计划

目标：桌面左侧展示真实评估进度；文字、语音每轮共用最多三题的候选集合，允许不选新题，实际新提问后冷却两轮。

方案依据：本任务中用户已确认的讨论。只修改患者对话桌面布局，手机保持现有交互。完成判定继续以有效结构化答案为准。

## 1、共享题目状态与查询
- [X] 1.1 新建 `backend/app/services/dialog_question_service.py`，从任务量表、有效答案、消息及 `interaction_event` 恢复题目状态，不新建数据库表。
- [X] 1.2 新增 `GET /api/dialog/{session_no}/question-progress`，校验患者归属与责任护士权限，输出 `session_id/current/total/turn_number/active_question_id/candidate_question_ids/questions`；题目字段 `question_id/question_code/question_text/scale_name/required/status/is_current/cooling_until_turn`，状态为 `unasked/asked/recorded`。
- [X] 1.3 公共接口 `load_question_context(db, session_no, source_message_no=None, patient_id=None, staff_id=None)` 返回上述字段及内部 `recorded_answers`；候选至多三题，优先未问，实际新提问 N 轮之后 N+1、N+2 禁止再选，N+3 才允许。
- [X] 1.4 `validate_decision(context, payload)` 验证 `selected_question_id` 与 `active_question_id`。选新题必须属于候选，澄清只可关联此前当前题，普通回应二者均可为空。候选展示不记录提问。
- [X] 1.5 `record_question_turn(db, session_no, message_no, source_message_no, selected_question_id, active_question_id)` 在 AI 消息成功保存后记录幂等 `question_turn` 事件并同步消息关联；中断、重试不得重复计轮，文字/语音共享历史。
- [X] 1.6 单元测试先覆盖 3 题上限、N+3 边界、空选择、澄清、非法选择、有效答案排除与重复提交。

## 2、文字与语音接入
- [X] 2.1 新增 SDK 内部 `report_question_choice` 工具，要求模型在可见回复前返回选择或空值；工具只报告选择，不直接更新完成进度。
- [X] 2.2 文字 Runner 每轮加载公共上下文，给候选和已记录摘要；校验选择后才允许输出，按实际选择持久化关联。删除必须按当前题下标推进的依赖，兼容历史无关联消息。
- [X] 2.3 语音 Gateway 每轮及恢复时刷新相同上下文；校验工具选择，在回复完成时持久化实际问句关联，中间工具响应、取消响应不记为已问。
