# 患者宣教确认领域事件 ID 错误

## 一、现象

患者孙志伟的任务 112 在收到戒烟宣教卡片后，点击“我已阅读并了解”返回
“宣教材料不存在或已失效”。

## 二、根因

任务 112 的数据库领域事件编号为
`EDU-EVENT-1D64A8E8D3524C6A8A3E504B5874C4A2`，对应 Redis Stream 消息编号为
`1787205471545-0`。

SSE 格式化逻辑原先使用 Redis Stream ID 覆盖信封 `event_id`。前端又把该字段保存为
宣教卡片 ID，因此确认接口收到的是传输游标，而后端按数据库领域事件编号查询，必然无法
找到材料事件。

API 快照恢复还采用增量 upsert，没有先移除 `sessionStorage` 中的陈旧卡片，可能在刷新后
同时保留错误卡片和数据库卡片。

## 三、修复

1. SSE 信封新增 `stream_id`，只保存 Redis Stream 游标。
2. `event_id` 保留事件模型自身的领域编号；没有领域编号的旧事件才回退到 Stream ID。
3. SSE 客户端使用 `stream_id` 断线续读和传输去重。
4. API 模式加载数据库快照前清理当前任务的领域卡片和呼叫状态。
5. 宣教确认接口对相同来源事件和材料的重复确认幂等返回首次结果。

## 四、验证

- 后端定向测试：13 项通过。
- 前端定向测试：5 项通过。
- 真实 API：任务 112 首次确认返回 `OK`，重复确认返回相同状态事件。
- 真实页面：刷新任务 112 后宣教卡片显示“已确认阅读”，浏览器控制台无错误。
