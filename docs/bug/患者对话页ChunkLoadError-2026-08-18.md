# 患者对话页 ChunkLoadError

日期：2026-08-18

## 1. 现象

患者访问 `/patient/dialogue/69` 时页面崩溃，浏览器报告
`ChunkLoadError`，无法进入任务对话页面。

## 2. 根因

本地 `next start` 生产进程启动于 2026-08-18 10:23:06，但
`.next/BUILD_ID` 对应的生产构建在 2026-08-18 15:50:11 被重新生成，
构建完成后没有重启旧生产进程。

这导致运行中的旧进程继续使用上一版路由和资源清单，而磁盘上的
`.next/static/chunks` 已被新构建替换。服务端返回的页面引用：

```text
/_next/static/chunks/003ippj34j95z.js
```

但该文件在当前生产输出中不存在，请求返回 HTTP 500。浏览器没有旧缓存时即触发
`ChunkLoadError`。

Next.js 16 的开发输出位于 `.next/dev`，它不是本次问题的直接原因。直接原因是
重新执行生产构建后继续复用构建前启动的 `next start` 进程。

## 3. 修复

1. 停止占用 3000 端口的本项目旧 `next start` 进程。
2. 在旧进程完全退出后重新执行 `pnpm build`。
3. 构建成功后启动唯一的 `pnpm start` 进程。
4. 在部署文档和前端 Agent 规范中补充生产构建、重启顺序。

## 4. 验证

- 新生产构建 ID：`oKBXMNuWHdmImsZt7W5gx`。
- 新构建完成时间：2026-08-18 17:33:03。
- 新生产进程启动时间：2026-08-18 17:33:23，晚于构建完成时间。
- `/patient/dialogue/69` 返回的 13 个 Next.js 静态资源均为 HTTP 200。
- 新浏览器标签页可以加载患者对话页面外壳。
- 浏览器控制台无 `ChunkLoadError` 和未处理 JavaScript 异常。

页面当前显示“任务不存在”是因为验证时 `127.0.0.1:8000` 没有后端 API 服务监听，
属于后续联调环境状态，与本次 chunk 加载故障无关。
