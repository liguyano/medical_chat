## 语音交互结论

建议借鉴 GPT Live 的“实时状态、中央语音存在感、播放可打断”，但不建议直接采用全程无感监听。

住院护理评估更适合：

- 患者明确点击后才申请麦克风权限。
- 语音模式默认为“点击开始回答”，停顿后自动结束本轮。
- AI 播报过程中患者可以直接说话打断。
- 识别结果先展示为“待确认转写”，患者可以确认发送或重新说一遍。
- 任何阶段都可以一键切换文字输入。
- 语音异常时自动保留文字输入，不阻塞评估。
- “找护士”始终可见，且与 AI 语音状态分开。

## 建议的交互状态

```text
idle
  -> connecting
  -> listening
  -> transcribing
  -> confirming
  -> thinking
  -> speaking
  -> listening       （患者打断 AI 播报）
  -> text_fallback   （麦克风/网络异常）
  -> closed
```

当前代码已有 `connecting / listening / transcribing / thinking / speaking / paused / error / text_fallback / closed` 等语音连接状态。新 UI 需要补一个面向患者的 `confirming` 展示态；如果后端暂时不能提供独立状态，可以在前端根据“收到转写、尚未提交”的事件派生，不要把转写内容直接当作最终答案提交。

## 建议的语音页面布局

1. 顶部：返回、评估标题、进度、找护士。
2. 中部：小医语音 Orb + 当前状态文案。
3. 中下部：最近一轮 AI 问题、实时转写、确认发送/重新说一遍。
4. 底部：大尺寸麦克风按钮、切换文字、打断播报。
5. 异常态：解释发生了什么、提供重新开启语音和文字输入，不使用不可理解的错误码。

语音动画应采用轻微呼吸和音量波纹，不使用持续闪烁或高饱和霓虹效果，避免给老年患者造成紧张感或误以为系统正在持续录音。
