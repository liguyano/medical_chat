# 评估量表数据库化设计说明

## 结论

建议采用“原始 PDF 不可变保存 + 解析结果进入暂存区 + 结构化字段落库 + 版本发布”的方式。

不建议继续把解析后的 JSON 作为护士日常编辑界面。JSON 可以保留为审计快照和导入/导出格式，但不应直接暴露为主编辑器。

## 推荐数据流

1. 上传或登记原始评估量表 PDF，保存文件地址、文件摘要、来源机构、上传人和上传时间。
2. 解析服务生成原始 JSON 暂存结果，记录解析器版本、解析耗时和解析状态。
3. 通过字段校验、关联校验和人工复核，把暂存结果转换为量表草稿版本。
4. 草稿版本写入结构化表：量表主档、版本、分组、题目、选项、计分规则、护理措施。
5. 医护在结构化编辑器中修改草稿，系统记录字段级变更。
6. 提交审核后生成发布记录；发布动作必须原子切换当前生效版本。
7. 患者端、任务创建和护理计划只读取“已发布版本”，不读取未发布草稿。

## 建议表结构

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `assessment_scale` | 量表主档 | `id`、`scale_code`、`scale_name`、`scale_type`、`status` |
| `assessment_scale_source` | 原始 PDF 与解析来源 | `scale_id`、`file_uri`、`file_sha256`、`parser_version`、`parse_status` |
| `assessment_scale_version` | 可编辑、可发布的版本 | `scale_id`、`version_code`、`version_name`、`lifecycle_status`、`based_on_version_id` |
| `assessment_scale_section` | 量表分组 | `version_id`、`section_code`、`section_name`、`sort_no`、`display_condition` |
| `assessment_scale_question` | 题目字段 | `section_id`、`question_code`、`question_text`、`answer_type`、`required`、`sort_no` |
| `assessment_scale_option` | 单选/多选选项 | `question_id`、`option_code`、`option_label`、`score`、`sort_no` |
| `assessment_scale_rule` | 计分、风险和显示规则 | `version_id`、`rule_code`、`rule_type`、`expression`、`priority` |
| `assessment_scale_action` | 护理措施 | `version_id`、`action_code`、`title`、`content`、`trigger_rule_id` |
| `assessment_scale_publish` | 发布记录 | `version_id`、`published_by`、`published_at`、`rollback_to_version_id` |
| `assessment_scale_change_log` | 变更审计 | `version_id`、`entity_type`、`entity_id`、`field_name`、`before_value`、`after_value`、`changed_by` |

`display_condition` 和规则表达式可以保留为受约束的 JSONB/表达式字段，因为它们属于规则配置，而不是用户日常编辑的整份文档。题目、选项和措施本身应使用关系表，便于排序、查询、校验和审计。

## 新配置页面应提供的能力

- 量表列表：搜索、科室适用范围、草稿/已发布筛选。
- 基本信息：量表名称、编码、用途、来源 PDF、适用科室。
- 分组与题目：拖拽排序、必填开关、题型、选项编辑、复制题目、删除前确认。
- 计分规则：规则类型、触发条件、分值/风险等级和优先级。
- 护理措施：风险等级对应的措施内容和启用状态。
- 预览：以患者端实际呈现方式预览题目、选项和条件显示。
- 版本与发布：草稿、提交审核、发布、回滚和变更记录。
- 字段校验：必填、编码唯一、选项完整、规则引用存在、发布前完整性检查。

## 与当前实现的关系

当前页面通过 `getScaleConfig()` 获取整份配置并写入 JSON 文本框。后续实现建议保留兼容接口一段时间，但新增以下领域接口：

- `listScaleVersions(scaleId)`
- `getScaleEditor(scaleVersionId)`
- `updateScaleMetadata(scaleVersionId, payload)`
- `createScaleSection(scaleVersionId, payload)`
- `updateScaleQuestion(questionId, payload)`
- `updateScaleOptions(questionId, payload)`
- `updateScaleRules(scaleVersionId, payload)`
- `submitScaleForReview(scaleVersionId)`
- `publishScaleVersion(scaleVersionId)`
- `rollbackScaleVersion(scaleVersionId)`

这样可以让 Mock 与 API 模式继续保持同一仓储接口，同时把 JSON 解析、结构化存储和患者端运行时读取彻底分离。
