# 后端详细设计方案

为了完成[docs/需求1-入院量表评估.md)]的需求, 我准备使用 langchain 框架作为 Agent 技术底座, Middleware 作为拦截中间件, 可以自由组装 AgentLoop.

我准备设计以下几个智能体:

1. 量表评估调度智能体, 它作为后台任务路由, 接收医护端选择的量表, 生成批量的量表问题队列, 引导 `对话智能体` 完成这些量表问题, 一方面减轻对话模型的推理损耗, 另一方面是提高量表问题的覆盖率, 避免问题不全面.

2. 面向患者交互的对话智能体-, 具备以下几个特点:
    - 1.1 语音对话: 使用端到端实时语音全双工大模型作为底座, 本次采用豆包实时语音模型作为实验, API文档如(https://docs.volcengine.com/docs/6561/2549778?lang=zh).
    - 1.2 引导式多轮对话：AI需引导患者与系统进行多轮对话交流，并引导患者回答映射到各类量表字段的问题，避免固定问答模板;
    - 1.3 共情能力：AI语言风格自然、亲切，符合老年人日常交流习惯，识别患者的情绪变化（如疲劳、焦虑、回避等）, 并进行适当回应与引导;

3. 字段抽取智能体: 结构化字段抽取任务, 任务相对简单.

## AgentLoop 设计方案

根据上述描述, 我认为各个智能体需要分开进程, 避免阻塞任务进行.

1. 量表评估调度智能体(Schedule Agent) AgentLoop 流程
量表评估调度智能体作为后台任务的资源调度, 需要拆解任务, 将杂乱离散的字段需求, 整理成一个有先后顺序的量表问题列表, 随后发送给 Dialog-Agent
后台资源调度celery任务一直跑(等待任务开启), 细节如下所示:
```text
医护端选择指定患者, 发布对话评估任务, 等待后台 Loading .
-> celery接收确定信号
-> Schedule Agent实例化
    -> 加载 system_prompt.
    -> user_prompt 组装记忆、时间、历史上下文.
    -> 加载工具列表 + Middleware列表
    -> 加载患者基础信息, 加载评估量表所有字段配置.
    -> 实例化成功(进程绑定)
-> Schedule Agent 输出量表问题列表(Task-todo)
```

由于患者与AI对话过程是一直进行的, 因此, Schedule Agent还需要获取患者与AI的对话记录, 判断是否正常开展.
```text
celery接收到 Dialog-Agent 发布信号(传输对话记录)
-> 获取进程绑定的实例化 Schedule Agent
-> 患者与AI对话记录组装User Prompt
-> Schedule Agent 根据上下文输出结果(即是否加入新的引导提示)
-> 发送给 Dialog-Agent AgentLoop
```


2. Dialog-Agent AgentLoop 流程
对话分为后台资源调度+用户交互两个阶段, 后台资源调度celery任务一直跑(等待任务创建对话智能体进程), 细节如下所示:
```text
医护端发布对话评估任务(患者号+量表评估调度智能体输出) -> 生成对话进程号(用户隔离)
-> celery接收确定信号, 拿到患者基础信息和Schedule Agent生成的量表问题列表(Task-todo)
-> dialog-agent 预热(提前初始化, 避免等待), 细节如下: 
    -> 加载 system_prompt
    -> user_prompt 组装记忆、时间、历史对话.
    -> user_prompt 组装评估任务(量表问题列表Task-todo + 加载用户基本情况)
    -> 加载工具列表 + Middleware列表
    -> 预热成功
-> 预热成功, 生成对话进程号, 该实例化智能体绑定进程号
-> 进程号将推送到患者端通知
-> (提前开场)对话智能体输出面向患者的开场提问. 例如: 开场白;
```

用户侧首次请求交互流程:
```text
患者端点击评估任务(拿到进程号)
-> 后端判断患者与进程号存在.
-> 根据进程号读取实例化对话智能体.
-> 患者端页面显示对话智能体输出的开场白.
-> 用户输入回答(传入的语音), 发送后端路由.
-> 注入智能体上下文(user_prompt).
-> 结合上下文, 对话智能体模型推理(实时语音全双工大模型).
-> 流式输出给患者端和医护端实时监控.

注意: 患者端此时交互完成了, 但是后台还需要将这份回答传给字段抽取模型, 抽取出结构化字段.
-> Middleware中间件 after_agent() 拦截结果
-> 将本轮模型问题+患者回答发送给另外两个后台任务: 字段抽取后台任务与量表评估调度后台任务.
```

用户侧多轮对话交互
由需求1可知, 当患者回答问题时, 出现了特征词(例如: 抽烟、喝酒等), 则需要字典库拦截, 引导模型对患者开展相关的宣教、知情同意书的签署.
并且, 量表评估进程是否遵循设定也需要把控, 所以多轮对话场景需要 Schedule Agent 的指令介入.

因此, 在多轮对话场景下, 交互流程如下所示:
```text
-> 患者多轮对话请求(文字或者语音)
-> 患者请求正则匹配字典库
-> 情况1: 匹配成功, 拦截请求, 强制注入新的约束提示词
    -> 抓取特征对应补充提示词, 注入模型上下文(User Prompt). 例如: `你必须询问患者抽烟多长时间`
-> 情况2: 未能匹配, 放行拦截.
-> 判断 Schedule Agent 是否发布新任务 
    -> 如果发布指令, 同样需要强制注入智能体上下文
-> 结合上下文, 对话智能体模型推理(实时语音全双工大模型).
-> 流式输出给患者端和医护端实时监控.

注意: 同理推送对话记录给后台.
-> Middleware中间件 after_agent() 拦截结果
-> 将本轮模型问题+患者回答发送给另外两个后台任务: 字段抽取后台任务与量表评估调度后台任务.
```

3. 字段抽取模型
这个任务比较简单, 就是写好提示词, 让模型按照指定JSON格式, 将AI对话记录, 按照评估量表的所有字段, 抽取出指定结构化字段, 然后把字段完成进度同步到医护端和患者端, 让用户能把控评估进度.

## 问题讨论与解决方案

### 1. 智能体实例的持久化和状态管理

**问题**: Celery任务通常是无状态的，智能体实例（包含上下文、历史记录）如何在多轮对话中持久化？

**决策**: 采用**方案B** - 使用Redis序列化智能体状态，按需加载（需要确保langchain对象可序列化）+ 数据库持久化对话历史

**实现方案**:
```python
# 智能体状态管理器
class AgentStateManager:
    async def save_agent_state(self, session_id: str, agent: DialogAgent):
        """序列化智能体状态到Redis"""
        state = {
            "system_prompt": agent.system_prompt,
            "tools": agent.tools,
            "memory": agent.memory.to_dict(),
            "context": agent.context,
            "metadata": agent.metadata
        }
        await redis.setex(f"agent_state:{session_id}", 3600, pickle.dumps(state))
    
    async def load_agent_state(self, session_id: str) -> DialogAgent:
        """从Redis恢复智能体状态"""
        state_bytes = await redis.get(f"agent_state:{session_id}")
        if not state_bytes:
            raise AgentNotFoundError(f"Agent state not found for session {session_id}")
        state = pickle.loads(state_bytes)
        agent = DialogAgent.from_state(state)
        # 从数据库加载完整对话历史
        history = await db.get_dialog_history(session_id)
        agent.load_history(history)
        return agent
```

**数据持久化策略**:
- **Redis**: 存储智能体实时状态（TTL=1小时，超时自动释放）
- **PostgreSQL**: 存储完整对话历史（永久保存，用于审计和模型优化）
- **每轮对话后**: 同时更新Redis状态 + 数据库历史记录

### 2. Schedule Agent 的触发时机和干预机制

**问题**: Schedule Agent何时触发？如何干预Dialog Agent偏离？

**决策**: 
- **触发时机**: 每一轮对话后都执行Schedule Agent检查
- **偏离判断**: Schedule Agent输出结构化字段 `{is_deviation: bool, constraint_prompt: str}`
- **干预方式**: 注入新prompt到Dialog Agent的下一轮user_prompt，引导模型拉回约束范围

**实现方案**:
```python
# Schedule Agent输出结构化Schema
class ScheduleAgentOutput(BaseModel):
    is_deviation: bool  # 是否偏离量表问题列表
    constraint_prompt: str  # 强制约束提示词（偏离时非空）
    completed_tasks: List[str]  # 已完成的量表问题ID
    remaining_tasks: List[str]  # 待完成的量表问题ID
    next_suggested_question: str  # 建议下一个提问的问题

# Middleware拦截逻辑
class ScheduleCheckMiddleware:
    async def after_agent(self, output, context):
        # 每轮对话后触发Schedule Agent检查
        dialog_history = context.get_history()
        schedule_result = await schedule_agent.evaluate(
            dialog_history=dialog_history,
            remaining_tasks=context.remaining_tasks
        )
        
        if schedule_result.is_deviation:
            # 将约束提示注入到下一轮Dialog Agent的上下文
            context.inject_constraint(schedule_result.constraint_prompt)
            logger.warning(f"Dialog deviation detected: {schedule_result.constraint_prompt}")
        
        # 发布进度更新事件
        await redis_stream.publish("schedule_events", {
            "session_id": context.session_id,
            "completed_tasks": schedule_result.completed_tasks,
            "remaining_tasks": schedule_result.remaining_tasks
        })
```

### 3. 字典库拦截的实现位置和优先级

**问题**: 字典库在哪里拦截？如何处理多个关键词？

**决策**:
- **拦截位置**: API层（接收请求时）
- **多关键词策略**: 都匹配出来后，都加入强制提示词约束

**实现方案**:
```python
# 字典库数据结构
keyword_library = {
    "抽烟": {
        "priority": 1,
        "constraint": "你必须询问患者抽烟的频率、持续时间、每天吸烟量",
        "education_material_id": "tobacco_education",
        "consent_form_id": "tobacco_consent"
    },
    "喝酒": {
        "priority": 2,
        "constraint": "你必须询问患者饮酒类型、频率、每次饮酒量",
        "education_material_id": "alcohol_education"
    },
    "青霉素过敏": {
        "priority": 3,
        "constraint": "你必须提醒患者下次就医时告知医生，并询问过敏反应症状",
        "alert": True
    }
}

# API层拦截器
@app.post("/api/dialog/message")
async def send_message(session_id: str, user_input: str):
    # 1. 字典库匹配
    matched_keywords = keyword_matcher.match_all(user_input)
    
    constraints = []
    if matched_keywords:
        # 按优先级排序
        matched_keywords.sort(key=lambda x: x["priority"])
        for keyword in matched_keywords:
            constraints.append(keyword["constraint"])
            logger.info(f"Keyword matched: {keyword['name']}")
    
    # 2. 加载智能体状态
    agent = await agent_manager.load_agent_state(session_id)
    
    # 3. 注入约束提示（追加模式，不覆盖）
    if constraints:
        agent.inject_constraints(constraints)
    
    # 4. 执行对话
    response = await agent.stream_chat(user_input)
    
    return StreamingResponse(response, media_type="text/event-stream")
```

### 6. 工具调用的技术细节

**决策**: 在Schedule Agent中增加**工具调用检查**机制

**实现方案**:
```python
# Schedule Agent检查逻辑增强
class ScheduleAgent:
    async def evaluate(self, dialog_history: List[Dict], remaining_tasks: List[str]):
        # 1. 检查对话偏离
        is_deviation = self._check_deviation(dialog_history, remaining_tasks)
        
        # 2. 检查工具调用完整性
        missing_tool_calls = self._check_tool_calls(dialog_history)
        
        constraint_prompt = ""
        if is_deviation:
            constraint_prompt = f"你偏离了量表问题列表，请回到问题：{remaining_tasks[0]}"
        
        if missing_tool_calls:
            constraint_prompt += f"\n你必须调用以下工具：{', '.join(missing_tool_calls)}"
        
        return ScheduleAgentOutput(
            is_deviation=is_deviation or bool(missing_tool_calls),
            constraint_prompt=constraint_prompt,
            completed_tasks=self._get_completed_tasks(dialog_history),
            remaining_tasks=remaining_tasks
        )
    
    def _check_tool_calls(self, dialog_history: List[Dict]) -> List[str]:
        """检查应该调用但未调用的工具"""
        missing_tools = []
        
        # 检查宣教材料工具
        if self._contains_keyword(dialog_history, "抽烟"):
            if not self._tool_called(dialog_history, "get_education_material", "tobacco"):
                missing_tools.append("get_education_material(category='tobacco')")
        
        # 检查知情同意书工具
        if self._contains_keyword(dialog_history, "手术"):
            if not self._tool_called(dialog_history, "trigger_consent_form", "surgery"):
                missing_tools.append("trigger_consent_form(form_type='surgery')")
        
        return missing_tools
```

### 7. 前后端实时同步的技术方案

**决策**: 模型流式输出 → redis-stream → SSE → 患者端+医护端（支持断线重连）

**架构设计**:
```text
Dialog Agent输出流
    ↓
Redis Stream (持久化)
    ↓
SSE推送服务 (读取stream并推送)
    ↓
患者端 + 医护端 (EventSource订阅)
```

**实现方案**:
```python
# SSE推送服务
@app.get("/api/sse/dialog/{session_id}")
async def sse_dialog_stream(session_id: str, last_event_id: str = None):
    """SSE推送对话流（支持断线重连）"""
    async def event_generator():
        # 断线重连：从last_event_id之后开始读取
        start_id = last_event_id if last_event_id else "0"
        
        while True:
            # 从Redis Stream读取新消息
            messages = await redis.xread(
                {f"dialog_stream:{session_id}": start_id},
                count=10,
                block=5000
            )
            
            for stream, message_list in messages:
                for message_id, data in message_list:
                    # SSE格式输出
                    yield f"id: {message_id}\n"
                    yield f"event: dialog_message\n"
                    yield f"data: {json.dumps(data, ensure_ascii=False)}\n\n"
                    start_id = message_id
    
    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no"
        }
    )

# 医护端监控多患者
@app.get("/api/sse/monitor")
async def sse_monitor_all(nurse_id: str):
    """医护端监控所有负责患者的对话"""
    async def event_generator():
        # 获取该护士负责的所有患者会话
        sessions = await db.get_nurse_sessions(nurse_id)
        streams = {f"dialog_stream:{s}": "$" for s in sessions}
        
        while True:
            messages = await redis.xread(streams, count=10, block=5000)
            for stream, message_list in messages:
                session_id = stream.split(":")[-1]
                for message_id, data in message_list:
                    data["session_id"] = session_id
                    yield f"id: {message_id}\n"
                    yield f"event: monitor_message\n"
                    yield f"data: {json.dumps(data, ensure_ascii=False)}\n\n"
    
    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

**前端断线重连逻辑**:
```javascript
// 患者端/医护端前端代码
let lastEventId = null;

function connectSSE() {
    const eventSource = new EventSource(
        `/api/sse/dialog/${sessionId}?last_event_id=${lastEventId || ''}`
    );

    });

        eventSource.close();
        // 5秒后自动重连
        setTimeout(connectSSE, 5000);
    };
}
```

## 工具设计方案

需求1中提到AI需要自动识别什么时候要对患者做宣教, 并且还是分级宣教. 然后, 在特殊情况, 还会自动发布知情同意书的签署组件, 让患者在页面上自动签字.
根据这部分动态的需求, 我认为做成工具调用(Function_call)的方式, 能够更符合模型的自动感知.

- 分级宣教支撑工具: 各类宣教材料做成字典匹配的工具服务, 模型感知意图后, 调用工具, 根据参数的不同, 获取宣教材料的原始文本, 实时语音双工大模型可以自己播报文本给患者.

- 语音播报工具: 需求中提到, 需要自动播报宣教文档, 假设模型不支持语音, 那么就让模型调用该工具, 把文本交给工具, 让工具自动播报给用户.

- 知情同意书签署工具: 同理写成工具, 并且前端做唯一性组件匹配, 当模型调用该工具后, 获取文档资料, 然后前端组件同步显示知情同意书的内容, 以及页面上出现签字按钮(这部分就是前后端的任务了, 只要保存签字内容就好)

### 8.2 错误处理机制

#### 8.2.1 模型推理超时
```python
class DialogAgent:
    async def chat_with_timeout(self, user_input: str, timeout: int = 15):
        """带超时的对话推理"""
        try:
            response = await asyncio.wait_for(
                self.engine.stream_chat(user_input),
                timeout=timeout
            )
            return response
        except asyncio.TimeoutError:
            logger.error(f"Model inference timeout after {timeout}s")
            # 返回友好提示
            return "我正在思考，请稍候片刻..."
        except Exception as e:
            logger.error(f"Model inference error: {e}")
            await self._save_error_snapshot()
            return "抱歉，我遇到了一些问题，请稍后重试。"
```

#### 8.2.2 患者无响应超时
```python
class SessionTimeoutManager:
    async def check_patient_timeout(self, session_id: str):
        """检查患者是否超时无响应"""
        last_active = await redis.get(f"session_last_active:{session_id}")
        if not last_active:
            return
        
        inactive_duration = datetime.now() - datetime.fromisoformat(last_active)
        
        if inactive_duration > timedelta(minutes=5):
            # 暂停对话会话
            await self.pause_session(session_id, reason="patient_timeout")
            # 发送通知
            await notification_service.send_to_nurse(
                session_id,
                "患者已超过5分钟无响应，对话已暂停"
            )
```

#### 8.2.3 字段抽取失败重试
```python
class FieldExtractionAgent:
    async def extract_with_retry(self, dialog_history: List[Dict], max_retries: int = 3):
        """带重试的字段抽取"""
        for attempt in range(max_retries):
            try:
                result = await self.extract(dialog_history)
                # 验证结果格式
                self._validate_extraction(result)
                return result
            except ValidationError as e:
                logger.warning(f"Extraction validation failed (attempt {attempt+1}/{max_retries}): {e}")
                if attempt == max_retries - 1:
                    # 最后一次失败，标记为待人工补录
                    await self._mark_manual_review(dialog_history)
                    return None
                await asyncio.sleep(1)  # 短暂延迟后重试
            except Exception as e:
                logger.error(f"Extraction error: {e}")
                return None
```

#### 8.2.4 Redis连接失败降级
```python
class RedisFallbackHandler:
    async def publish_with_fallback(self, stream_key: str, data: dict):
        """带降级的Redis Stream发布"""
        try:
            await redis.xadd(stream_key, data)
        except RedisConnectionError:
            logger.error("Redis connection failed, fallback to database")
            # 降级：直接写入数据库消息队列表
            await db.insert_message_queue(stream_key, data)
        except Exception as e:
            logger.error(f"Publish failed: {e}")
            raise
```
