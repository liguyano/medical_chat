# ESP32-S3 语音评估设备接入说明

适用设备为亚博智能 ESP32-S3-N16R8，固件使用 ESP-IDF。本文对应后端 TCP 协议 v1，供固件开发与联调使用。

## 1. 联调前准备

后端同事提供服务器 IP、TCP 端口（默认 9100）、设备 ID 和设备密钥，并在护士端「任务管理 → 创建任务」选择「嵌入式设备」，将任务分给该 ID。设备 ID 由后端预先登记，例如 `ESP32-001`。连接时发送分配给设备的原始密钥，后端保存的 SHA-256 摘要无需写进固件。

设备通过 Wi-Fi 主动建立原生 TCP 长连接。首版在受控局域网或私网使用合成音频联调。设备密钥和 PCM 在此协议中均明文传输，真实患者数据须使用加密通道。

## 2. TCP 帧格式

| 字节偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 1 字节 | 帧类型。0x01 为控制帧，0x02 为音频帧。 |
| 1 | 4 字节 | 无符号负载长度，网络字节序（大端），有效范围 1–8192。 |
| 5 | 按帧头长度 | 控制帧为 UTF-8 JSON 对象，音频帧为原始 PCM。 |

接收时先读满 5 字节，再读满负载长度。一次 `recv()` 可能只收到半个帧，也可能收到多帧。发送也需要处理短写。控制帧无换行或 NUL 结束符。音频长度必须是偶数，按采样点切分。帧头长度为大端，PCM 样本为小端。

示例控制帧 `{"type":"PING"}` 的帧头为 `01 00 00 00 0F`，后接 15 字节 JSON。

## 3. 连接与任务领取

| 步骤 | 设备发送 | 服务端返回 |
|---|---|---|
| 鉴权 | `{"type":"HELLO","version":1,"device_id":"ESP32-001","secret":"<设备密钥>"}` | `{"type":"HELLO_OK"}` |
| 查询任务 | `{"type":"GET_TASK"}` | `{"type":"TASK","task_no":"TASK-…","ready":true}` |
| 开始评估 | `{"type":"START"}` | `{"type":"STARTED"}` |
| 保活 | `{"type":"PING"}` | `{"type":"PONG"}` |

无任务时返回 `task_no:null, ready:false`。任务还在准备时，可能有任务编号且 `ready:false`。建议每 3–5 秒查询一次，只有 `ready:true` 才发 `START`。服务端按设备 ID 查找已分配会话，设备无需提交任务编号或患者信息。等待模型回复或空闲时也要保活，建议每 20 秒发一次 `PING`。服务端等待一帧完整上行消息的超时为 45 秒。

## 4. 一轮录音与播放

1. 收到 `STARTED` 后允许开始录音。建议短按 BOOT 发 `{"type":"RECORD_START"}`，收到 `{"type":"RECORDING"}` 后开始采集并发送音频帧。
2. 再按一次 BOOT，先发送完采集缓冲里的最后一帧，再发 `{"type":"RECORD_END"}`。每轮至少上传一帧音频。该消息只提交本轮录音。
3. 保持接收。收到 `{"type":"PLAY_START","sample_rate":16000}` 后准备播放，随后把 0x02 音频帧放入播放缓冲。收到 `{"type":"PLAY_END"}` 后播完缓冲，再允许下一轮录音。

上下行均使用 **16 kHz、PCM16 有符号小端、单声道**，无 WAV 头、无 Base64。建议录音以 20 ms 为一帧（320 个采样，640 字节）。使用板载 ES8311 的 I2S RX 采集，播放时沿用厂商示例的 ES8311 DAC 和 NS4150 功放配置，将收到的单声道样本复制到 I2S 左右声道。确认扬声器已连接。首版用半双工，等待模型回复和播放期间不开始新一轮录音。

## 5. 异常与重连

控制帧错误格式为 `{"type":"ERROR","code":"…"}`。

| 错误码 | 固件处理 |
|---|---|
| `DEVICE_CONNECTED` | 同一 ID 仍有旧连接。关掉本次 socket，退避后重连。 |
| `TASK_NOT_READY` | 回到待命，继续查询任务。 |
| `INVALID_STATE` | 当前操作顺序无效。停止本次操作，重新同步状态。 |
| `SESSION_BUSY`、`TASK_ENDED` | 服务端会关闭连接。停止录放，重连后重新查任务。 |
| `CONNECTION_FAILED` | 握手、帧格式或会话处理失败。检查凭据和报文，服务端会关闭连接。 |
| `VOICE_ERROR` | 上游语音处理异常。结束本轮本地等待，必要时重连。 |

`RECORD_END` 后没有固定的同步应答，也可能没有可播放音频。建议为等待回复设置超时，超时后重连并提示用户重试。TCP 断开时停止录放，清空未播放和未发送缓冲，按 `HELLO → GET_TASK → START` 重新进入任务。不要补发旧音频或旧 `RECORD_END`，避免重复提交。后端保留已落库的对话和评估进度。

## 6. 真机联调验收

- 设备鉴权成功后护士端显示在线，收到分给本设备的任务。
- 录一段合成测试语音，设备收到并完整播放模型回复，音高和速度正常。
- 连续两轮验证录音、等待和播放切换。播放期间不会把扬声器声音录回。
- 在录音和播放期间各断网一次，恢复后能重新领取原任务，旧音频不会继续发送或播放。
- 任务完成或取消后，设备可回到待命并领取下一项任务。
