# 第一期文本问诊前后端真实接口联调审查

## 1. 审查范围

- 在院患者与已发布量表查询。
- AI 对话任务创建、会话及评估实例初始化。
- AI 先问、患者回答、AI 下一问的文本问诊循环。
- Schedule、Dialog、Extraction 三个 Agent 的 Redis Stream 协作。
- 患者端与护士端 SSE、历史恢复、字段抽取和任务完成状态。
- 桌面端与 390px 移动端页面。

## 2. 联调发现并修复的问题

- 前端把护士原型编码 `N001` 当作数据库整数主键提交。
- AI 整句事件被历史快照与 SSE 回放重复拼接，且输入框未结束等待状态。
- 患者答案到达后页面进度未更新。
- Extraction Agent 读取不存在的 `question_text` 字段，导致抽取失败。
- 抽取结果查询依赖未声明的 ORM relationship，落库后 REST 快照返回 500。
- Redis 阻塞读取超时会终止长驻 Worker 或 SSE。
- 浏览器原生 EventSource 断线事件被误当成业务 `error` 消息解析。
- API 模式仍显示语音、宣教、固定 45% 进度等 Mock 文案。
- 会话结束事件只更新任务状态，没有同步患者会话完成态。

## 3. 验证结果

- 真实任务 `67` 使用 ADL 量表完成 10 轮问诊。
- AI 首问在患者输入前产生，后续问题严格按 Task-todo 顺序推进。
- 后端任务状态为 `pending_review`，会话状态为 `completed`。
- 对话历史共 20 条消息，患者答案与对应 AI 问句使用相同轮次。
- 10 个字段全部写入提交、答案和选项表，并可通过 REST 与 SSE 恢复。
- 护士监控无需刷新即可看到患者回答、AI 下一问、进度和抽取字段。
- 患者端完成页、护士待复核入口、桌面端和 390px 移动端均正常。
- 干净浏览器会话控制台无错误。

- 后端变更文件 Ruff 通过。
- 后端 `compileall` 通过。

## 5. 第一期边界

真实 API 模式仅开放文本问诊、字段抽取和护理监控。语音、传统问卷、知情同意、
宣教、人工介入、评分和护士复核提交仍属于后续阶段，前端 API 模式不会调用这些
尚未提供的接口。
