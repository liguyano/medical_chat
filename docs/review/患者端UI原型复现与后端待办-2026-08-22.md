## 四、需要安排的后端待办

### 4.1 患者身份核验字段与原型不完全一致

原型使用“任务编号 + 证件号码后四位”，但当前 API 登录契约为“完整身份证号 + 手机号”。为保证真实登录不被破坏，API 模式继续显示并提交完整身份证号与手机号；Mock 模式按原型显示任务编号和后四位。

如需 API 模式完全对齐原型，后端应新增安全的患者核验契约，例如：

- 输入：任务令牌或任务编号、证件后四位，可选短信/住院腕带二次校验。
- 输出：沿用当前患者 HttpOnly Cookie 和 `PatientPortal`。
- 安全要求：限制尝试次数、避免通过任务编号枚举患者、记录核验审计。

前端预留位置：`frontend/src/app/patient/page.tsx` 的 `apiMode` 字段分支和 `handleVerify()`。

### 4.2 语音“转写待确认”缺少后端草稿事件

当前 Voice Gateway 只提供连接状态、音频和完成控制标记，没有向页面提供可编辑的转写草稿，也没有“确认发送/重新录制”对应的控制消息。API 模式因此只能展示等待状态，不能把真实转写文本放入确认卡。

建议后端补充：

- 服务端事件：`transcript_ready`，至少包含 `transcript_id`、`text`、`is_final`、`turn_no`。
- 客户端控制：`confirm_transcript`、`retry_transcript`，使用 `transcript_id` 幂等关联。
- 确认前不得把草稿计入结构化答案进度。

前端预留位置：

- `frontend/src/app/patient/dialogue/[taskId]/page.tsx` 的 `pendingVoiceTranscript`、`confirmVoiceTranscript()` 和转写确认卡。
- `frontend/src/lib/transports/voiceSocket.ts` 后续可在不改页面结构的情况下分发新增控制事件。

### 4.3 知情同意条款快照与音频资源

独立知情同意页当前保留现有本地条款作为回退，并通过既有 `submitConsent()` 提交。后端尚未为该页面提供任务绑定的条款快照、音频地址、真实时长和播放完成状态。

建议后端提供：

- 按任务读取知情同意表单及条款快照。
- 条款字段增加患者文本、音频相对地址、时长、版本和强制确认标记。
- 播放完成/理解状态支持幂等持久化，刷新后可恢复。

前端预留位置：`frontend/src/app/patient/consent/[taskId]/page.tsx` 的 `initialClauses` 回退、`markListened()` 和条款音频卡。

### 4.4 住院助手真实问答与语音

住院助手当前严格限制为生活问题，并在超出范围时引导联系护士；文字回答使用前端演示字典，语音入口展示待接入提示。后端尚无独立生活助手会话、知识配置或语音通道。

建议后端提供：

- 病区生活知识查询或受控问答接口，不复用护理评估答案抽取流程。
- 明确的“无法回答/需护士处理”领域事件。
- 如启用语音，提供与护理评估隔离的会话和权限边界。

前端预留位置：`frontend/src/app/patient/assistant/page.tsx` 的 `answers`、`send()` 和语音入口。

### 4.5 扫码、患者通知与病区指南

扫码核验、患者通知列表和独立病区指南在当前后端契约中没有对应能力。前端已完整保留入口、状态和视觉，不阻塞现有护理任务流程。后续可以分别接入二维码一次性令牌、患者未读通知和病区内容配置；不应复用医护端接口或在前端写死生产数据。
