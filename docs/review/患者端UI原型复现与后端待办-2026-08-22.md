## 四、需要安排的后端待办

### 4.1 患者身份核验字段与原型不完全一致

原型使用“任务编号 + 证件号码后四位”，但当前 API 登录契约为“完整身份证号 + 手机号”。为保证真实登录不被破坏，API 模式继续显示并提交完整身份证号与手机号；Mock 模式按原型显示任务编号和后四位。

如需 API 模式完全对齐原型，后端应新增安全的患者核验契约，例如：

- 输入：任务令牌或任务编号、证件后四位，可选短信/住院腕带二次校验。
- 输出：沿用当前患者 HttpOnly Cookie 和 `PatientPortal`。
- 安全要求：限制尝试次数、避免通过任务编号枚举患者、记录核验审计。

前端预留位置：`frontend/src/app/patient/page.tsx` 的 `apiMode` 字段分支和 `handleVerify()`。

### 4.2 语音转写提交策略（已补齐）

Voice Gateway 已提供 `transcript_ready`、`confirm_transcript`、`retry_transcript` 兼容协议。
生产会话默认 `require_transcript_confirmation=False`：ASR 完成后直接落正式患者语音消息，
发布 `PatientAnswerEvent`/SSE 并派发结构化抽取 Worker；患者端收到 `transcript_ready` 后
也会自动发送确认控制，兼容仍要求确认的旧后端会话。这样不会出现“模型已经回答但页面卡在
确认发送”的阻塞。

前端转写状态已调整为悬浮层：只有用户点击开始语音、录音/识别/思考/播报或异常时显示，
不参与消息列表排版；提交完成、关闭语音或切换文字后自动收起。Mock 模式仍保留“确认发送/
重新说一遍”卡，便于原型演示和协议回归。

## 九、语音竞态、患者称呼与宣教反问修复（2026-08-22）

### 9.1 `Conversation has no active response` 根因与修复

问题出现在实时语音网关的响应竞态：

- 工具调用结果写回后无条件发送 `response.create`；
- 患者连续快速停顿或打断播报时，`response.cancel` 可能与上游
  `response.done` 乱序；
- 本地状态仍认为有响应，但 Qwen 已经没有活动响应，于是返回
  `Conversation has no active response`；
- 前端收到普通错误后会关闭语音并切换文字，导致语音会话卡死。

已完成修复：

- 工具调用按 `call_id` 幂等，重复事件不会重复执行宣教或呼叫护士；
- 工具结果只登记一个待续响应，等待当前响应结束后串行发送 `response.create`；
- 增加响应创建/取消状态保护和最多三次可恢复重试；
- 对无活动响应竞态清理本地过期状态并恢复 `listening`，不再向患者发送错误降级消息；
- 前端传输层对同类旧后端错误也做兼容恢复，不关闭麦克风、不切换文字。

### 9.2 患者称呼与沟通情感

Dialog system prompt 现在根据患者偏好、年龄和性别生成保守的礼貌称呼：

- 高龄男性/女性：爷爷/奶奶；
- 中老年男性/女性：叔叔/阿姨；
- 成年男性/女性：哥哥/姐姐；
- 未成年人：弟弟/妹妹；
- 性别未知或资料不足：使用“您”，不武断猜测。

开场最多一次使用“姓名 + 礼貌昵称”，后续优先使用昵称或“您”，禁止每轮重复完整姓名。
文本首问、文本收尾和实时语音共用这套规则。历史中已经生成的旧消息不会被自动改写，
新建响应会使用新提示词。

### 9.3 宣教 teach-back 机制

Dialog 和 Schedule 提示词均加入宣教理解闭环：

1. 调用宣教工具并展示/播报核心内容；
2. 用患者能理解的短句反问，请患者用自己的话复述最重要的风险和行动要求；
3. 等待患者下一轮回答，由 AI 判断是否覆盖核心信息；
4. 理解正确后先肯定，再恢复量表评估；
5. 复述错误、遗漏、表示不清楚或拒绝复述时重新解释并再次反问；
6. 卡片展示、自动播报、患者说“知道了”或前端 acknowledged 状态均不能直接视为理解完成。

工具结果新增 `teachback_required` 和 `teachback_prompt` 字段作为模型上下文提示，
没有改变既有工具名称、参数或前端领域事件结构。

当前 teach-back 是否完成由 Dialog Agent 根据患者复述在对话上下文中判断，避免在本次修复中
擅自新增接口或改变医护端事件契约。若后续要求医护端单独看到“宣教理解通过/未通过”审计
状态，需要后端新增 teach-back 领域事件或状态字段，并由患者复述消息与对应宣教事件建立
幂等关联；该后续接口位置已保留，当前不会把前端“已确认阅读”冒充为理解通过。
