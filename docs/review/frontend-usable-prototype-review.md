# 前端可用交互原型审查记录

> 审查日期：2026-08-16
>
> 审查分支：`feat/frontend-usable-prototype`
>
> 审查范围：`docs/前端详细设计需求方案.md` 对应的医护端、患者端、状态管理和响应式交互。

## 1. 审查结论

当前前端已经达到“可用交互原型”标准，可以在不依赖后端、HIS、真实模型、ASR/TTS和电子签名服务的情况下，完整演示：

```text
护士创建任务
→ 患者核验并完成采集
→ 风险宣教和知情同意
→ 护士实时监控
→ 护士差异复核
→ AI质量评价
```

视觉风格沿用现有暖白背景、陶土橙主色、衬线标题、圆角卡片和轻阴影，没有引入独立的新视觉体系。

## 2. 本轮真实浏览器发现并修复的问题

### 2.1 护士布局生产构建失败

- 现象：服务端预渲染 `/nurse/config` 时访问 Zustand `persist.hasHydrated()` 报错。
- 原因：持久化 API 在服务端无浏览器存储时不可直接读取。
- 修复：使用 `useSyncExternalStore` 区分服务端快照和客户端 hydration，再执行登录态路由保护。

### 2.2 Zustand 选择器导致 React 无限更新

- 现象：进入 `/nurse/patients/5` 后触发 React 错误边界。
- 原因：Store 选择器中直接 `filter()` 或返回 `?? []`/`?? {}`，每次获取快照都生成新引用。
- 修复：选择稳定的 Store 原始字段，在组件渲染阶段派生数组或回退值；同步处理监控、质评、任务详情、问卷、复核和对话页的同类风险。

### 2.3 过敏分支问答与结构化字段错位

- 现象：患者回答有过敏史后，AI追问严重反应，但下一轮输入被保存为行动能力。
- 原因：固定七轮脚本增加了条件追问文本，却没有增加对应状态节点。
- 修复：该轮改为记录过敏风险提示并继续询问行动能力，使提示语、下一轮回答和结构化字段保持一致。

### 2.4 传统问卷混入未选量表

- 现象：任务 2 仅配置入院评估、ADL和跌倒风险，页面仍出现 NRS2002 题目。
- 原因：题目仅按条件逻辑过滤，没有按任务 `scaleIds` 过滤。
- 修复：建立量表ID与题目分组映射，先按任务量表包过滤，再执行条件题逻辑；进度总数同步改为当前可见必填题数。

### 2.5 缺少断网反馈

- 现象：文档要求连接中断状态，原型没有显式反馈。
- 修复：新增全局网络状态组件；断网时提示内容已保存在本机，恢复在线后自动消失。

### 2.6 其他体验修正

- 晚间仍显示“早上好”改为不受时区影响的“您好”。
- 登录输入框增加浏览器自动填充语义。
- 增加加载页、404页和运行时错误恢复页。
