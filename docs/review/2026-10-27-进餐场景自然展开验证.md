# 进餐场景自然展开验证

## 问题和修复
原始进食能力问句在共享任务、文字首问/后续、规划和语音剩余题中直接出现，模型容易在换题时照着问。新增 conversation_scenes 区分 clinical_reference（原题及时间条件）与 scene_guidance（生活场景路径）：先具体食物，再餐具、夹取送入口等实际过程。禁止直接从游戏跳到“吃饭需要帮忙吗”。

原题条件、选项、计分及 Extraction 不改；MMSE/MoCA/Mini-Cog 排除场景替换。喜好、餐具或做饭均不能证明独立进食，仍须明确的实际动作和协助原话，不足则保持缺项。
同步正常语音、提前结束恢复和结束检查工具返回，避免恢复路径或工具把裸原题重新带回。相关 JSON 仅供模型内部使用，不改浏览器 API 协议。

## 验证
- 共享语音输入、恢复入口和结束工具返回的场景缺失测试均先失败后修复。
- 完整单元测试和所有改动 Python 文件 Ruff 检查通过，最终数量见计划完成记录。
- 沿用用户此前明确授权的相同阿里云 qwen3.8-max 服务，仅发送虚构内容，文字与语音指令文本模拟各四轮共2项通过。
- 已复现的真实模型输出路径：游戏看清→“最近一顿吃了什么/喜欢吃什么”→“面条用筷子还是勺子”→“夹面送到嘴里顺手吗”。普通回复≤60字符、至多一个问号，没有笼统进食帮助问句。语音最后在患者明确实际动作后调用原生结束检查。
- 独立只读审查无确定新增缺陷；审查建议统一工具返回已补充，并有先失败后通过的回归。

## 边界
有限模型样本不保证每次输出；语音组是提示词的文本模拟，未验证真实麦克风/ASR/TTS，也未验证真实 Extraction 进度入库。截图中的当前运行会话需重启后端并重新建立连接才能加载新上下文。
本次不访问真实患者数据、不启动应用服务；仅合并本地dev，main和备份不改、不推送，用户原有文件不动。
