# 患者宣教确认领域事件 ID 修复代码审查

## 一、审查范围

- 后端 SSE 信封格式化与宣教确认幂等逻辑。
- 前端 SSE 协议、断线游标、领域 Store 和患者对话快照恢复。
- 后端与前端回归测试。

## 二、审查结论

- 领域事件 ID 与 Redis Stream 游标职责已经分离。
- SSE `id:` 行仍保持 Redis Stream ID，不影响 EventSource 原生断线续读。
- 自定义重连参数改用 `stream_id`，不会把 UUID 或业务编号传给 Redis `XREAD`。
- 宣教卡片使用领域事件编号，可与 `interaction_event.event_payload.event_id` 稳定关联。
- 快照清理仅影响当前任务，不会清除其他患者任务或全局护士提醒。
- 重复确认不再创建重复状态事件，患者与任务权限校验保持不变。

## 三、风险检查

- 历史 SSE 消息没有领域事件编号时仍回退到 Stream ID，保持旧事件兼容。
- API 历史事件没有 `stream_id`，但不参与 SSE 断线续读，不影响恢复。
- 当前改动不改变数据库结构，无需 Alembic 迁移。

- 后端定向测试通过。
- 前端定向测试和 TypeScript 类型检查通过。
