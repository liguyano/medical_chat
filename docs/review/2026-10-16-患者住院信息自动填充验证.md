# 患者住院信息自动填充验证

## 实现与审查
- 新增/编辑表单移除住院号、床号、护理级别、入院来源的输入、校验和提交字段。
- 后端为缺省新建请求生成 ZY-日期-UUID 住院号，其余三项默认待分配、待评定、未登记。
- API 序列化省略未提供字段；编辑保持历史值，显式旧接口字段仍兼容。
- Mock 提供同样占位值，省略编辑时保留历史非默认值以及原有空值；Mock 住院号使用 ZY-UUID，与后端格式不同但均为系统生成标识。
- 独立审查无阻塞问题，无数据库结构变更。

## 验证
- 新回归测试先确认失败：缺省住院号/床号被拒、表单仍有输入、空护理级别/来源被发送、Mock 未自动填写。
- 修复后前端全量 115 项、后端单元 326 项通过；补充历史非默认四项保留断言后患者仓储 8 项通过。
- 前端类型检查、正式构建通过；全量 lint 无错误，报告页原有 3 条未使用导入警告；后端相关文件 Ruff 通过。
- 真实 PostgreSQL 患者集成测试 1 项通过：确认开发环境后，由真实 FastAPI 应用接口新建省略四项的患者，独立数据库连接核对患者与住院记录、自动住院号及三项占位值，编辑后再次查询确认不变，finally 清理自建记录。
- 集成测试保留现有 Redis close 弃用警告，不影响结果。
- 当前用户前端为 API 模式并指向公网后端，浏览器访问受医护登录会话限制；静态真实组件测试覆盖新增/编辑表单不渲染四项，本轮不将其描述为完整浏览器端到端验证。
