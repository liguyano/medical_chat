# 任务首问准备与诊断上下文代码审查

## 审查范围

- 医护端创建 AI 对话任务后的 `Schedule prepare → Dialog preheat → Dialog opening` 流水线。
- 患者端任务可见性、医护端阶段输出和失败重试。
- Agent 患者上下文是否仅包含当前住院记录的疾病诊断。

## 审查结论

1. AI 任务创建后先持久化为 `queued`，患者端查询要求同时满足
   `preparation_status=ready` 和 `patient_visible_at IS NOT NULL`。
2. 首问消息保存成功后才进入 `ready` 并设置患者发布时间；准备失败任务保留医护可见的阶段错误，
   不会出现在患者任务列表。
3. 重试接口按责任护士校验，并使用任务行锁保护失败状态检查，重复点击不会重复派发准备链。
4. Agent payload 只新增当前住院记录的 `diagnosis_snapshot`；过敏史、入院来源、护理级别未进入
   payload。Schedule/Dialog Prompt 均声明该快照只供内部评估排序和风险理解，不得向患者宣告诊断，
   不得据此自行诊断或调整治疗。
5. 量表问题列表和首问文本以 `preparation_detail` 快照返回医护端，前端轮询展示，并在失败状态提供
   “重试准备”按钮。
