# 实时语音结束流程修复代码审查

## 审查范围

- 后端语音完成协调、Qwen Realtime 响应收尾、WebSocket 主动关闭。
- 前端 PCM 播放排空、语音连接资源释放、任务完成 UI 时序。

## 审查结论

本次修改保持纯文本 Dialog Agent 完成链路不变。实时语音完成改为由
“Extraction 结构化进度完整”和“最后一轮可见 Qwen 响应完成”共同触发，
并通过 Redis 跨进程协调。患者端在显示任务完成前，还会等待 Voice Gateway 的
`response_completed` 顺序标记和本地 PCM 播放队列排空。

未发现阻塞合并的问题。

## 审查中发现并修复的问题

1. Function Calling 的中间 `response.done` 可能被误判为最后回复：
   增加待续响应计数，只在工具后的最终可见响应结束时进入完成协调。
2. 空响应可能提前满足完成条件：
   没有文字和音频的响应不登记为患者可见回复完成。
3. SSE 与 WebSocket 跨连接存在乱序窗口：
   Gateway 在发布任务结束状态前发送 `response_completed`，前端串行处理
   WebSocket 消息后再等待播放器排空。
4. 播放器 `AudioBufferSourceNode` 登记与 `onended` 存在极短竞态：
   先绑定结束回调并登记音频源，再调用 `start()`。
5. 服务端 `closed`、网络错误或语音错误只改变状态但未释放麦克风：
   统一停止 MediaStream、关闭 AudioContext、播放器和 WebSocket。
6. 患者任务页错误调用医护专用 `/api/tasks`：
   新增 `listPatientTasks()`，患者端只访问 `/api/patients/me/tasks`。
