# 护士端对话逐条质评与整体质量评价代码评审

## 评审范围

- 后端 `interaction_message_feedback.score` 字段、质量评价四张表、Alembic 迁移、Schema、服务和 API 路由。
- 前端护士监控详情页、整体质量评价详情页、仓储/API 映射、Zustand 会话状态。
- Mock/API 双模式、逐条评价更新、整体评价加载与保存、桌面和 390px 移动布局。

## 评审结论

评审通过。实现满足“左侧任务进度—中间对话回放—右侧本轮 AI 质评”的护士端布局，患者消息没有 AI 质评入口；单条 AI 消息支持 1～5 分、符合预期/存在问题、问题标签多选和自由备注，并支持新增、更新和刷新回显。整体质量评价保留 AI 对话质量与 AI 评估质量两组可配置维度，支持快捷分值和总体自由输入。

AI 评估质量的 `quality_review.target_id` 由后端解析为任务最新已完成 `assessment_submission.id`，不会误指向任务或评估实例。进行中任务没有可评价的 AI 评估提交时，后端拒绝评估质量分组，前端显示“等待评估结果”，但仍允许保存 AI 对话质量。

## 重点检查与修复

1. 迁移一致性检查发现新质量评价表缺少通用审计列注释，已补入迁移并通过 `alembic check`。
2. 修复整体评价页在“进行中任务先保存对话评价、任务完成后再打开”时空评估分数字典覆盖默认分值的问题。
3. 统一后端数字护士 ID 与前端演示工号（例如 `1` 与 `N001`）的边界转换，避免已保存评价被错误隐藏。
4. API 模式加载整体评价时按当前护士重新读取并清理无对应记录的本地缓存，避免不同护士在同一浏览器会话中串看评价。
5. 移动端选中 AI 消息后自动定位到质评卡片，并为评分、标签和选中消息补充 `aria-pressed` 状态。
6. 更新 API 文档响应字段，去除旧的 `rating_id`/`rating_type` 示例。
