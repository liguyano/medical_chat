# 医护端历史任务跨浏览器恢复修复审查

日期：2026-08-19

## 根因

医护监控中心、任务管理和工作台之前直接读取 Zustand `sessionStorage`。医护登录后没有调用后端任务列表接口，因此同一浏览器刷新可以看到历史缓存，换浏览器则只剩初始 Store 数据。任务 109 在数据库中仍存在，且 `assigned_nurse_id=1`，不存在数据丢失。

## 修复

- 后端新增 `GET /api/tasks`，要求医护登录，按当前 `staff_account.id` 查询 `care_task.assigned_nurse_id`，返回全部历史、进行中、待复核和已完成任务。
- 复用完整 `BackendTaskDto`，保留任务真实进度、患者信息、量表进度和人工呼叫状态。
- 前端 `ApiCareRepository.listMyTasks()` 改为调用 `/api/tasks`。
- `NurseLayout` 在 `/api/auth/staff/me` 成功后同步刷新任务列表，并替换本地 Store，避免旧 sessionStorage 污染。
- Mock 模式保持原有演示任务行为。

## 验证

- 数据库核验：任务 109 的 `assigned_nurse_id=1`。
- 使用 N001 / 123456 登录后请求 `GET /api/tasks`：返回 9 条任务，包含任务 109、患者周海燕。
- 后端任务查询单元测试通过。
- 前端仓储回归测试覆盖 `/api/tasks` 和任务 DTO 映射。
