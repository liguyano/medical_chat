## 一、测试环境与前置

### 1.1 依赖服务
| 组件 | 用途 | 备注 |
|------|------|------|
| PostgreSQL | 领域数据落库（patient/encounter/care_task/interaction_*） | 需先跑 Alembic 迁移 `26533d4669bd` |
| Redis | 分布式锁 + Redis Stream（`dialog_stream:{session_no}`） | SSE 与并发锁依赖 |
| Celery worker | 消费 `dialog_agent_preheat` / Dialog Agent 异步产出 | 集成/E2E 需启动；纯 API 单测可 mock |

### 1.2 测试数据准备（fixture）
- 至少 1 个 `patient`、其名下 1 个 `patient_encounter`。
- 1 个 `care_task`：`collection_mode="ai_dialogue"`、`deleted=0`（用于成功路径）。
- 1 个 `care_task`：`collection_mode` 非 `ai_dialogue`（用于 ERR_DIALOG_004 路径）。
- 关键词规则：调用 `InteractionRuleImporter.import_from_file()` 导入
  `app/data/keyword_library.json`（5 条：KW_SMOKING/KW_DRINKING/KW_ALLERGY/KW_EDUCATION/KW_CONSENT）。

### 1.3 建议测试分层
- **单元测试**：不依赖 DB/Redis，纯函数与匹配逻辑（关键词匹配器、SSE 消息格式化、错误码工具）。
- **集成测试**：`TestClient` + 真实/内存 DB + 真实/fake Redis，覆盖 API 全链路（不含模型产出）。
- **E2E 测试**：启动 FastAPI + Redis + Celery，验证「发消息 → Agent 异步产出 → SSE 回推」闭环。

## 二、步骤7：字典库与关键词匹配

### 2.1 关键词库导入 `InteractionRuleImporter`（集成）
| 用例 | 步骤 | 预期 |
|------|------|------|
| KW-IMP-01 首次导入 | 空表调用 `import_from_file()` | 返回 `{created:5, updated:0, total:5}`，库中 5 条 `interaction_rule` |
| KW-IMP-02 幂等重入 | 连续调用两次 | 第二次 `{created:0, updated:5, total:5}`，行数仍为 5，不新增 |
| KW-IMP-03 内容更新 | 修改 JSON 某规则的 `priority`/`action_payload` 后再导入 | 对应行字段被更新，`updator="system"` |
| KW-IMP-04 缺省路径 | 不传 path 调用 | 使用 `_DEFAULT_LIBRARY`（app/data/keyword_library.json）成功导入 |

### 2.2 关键词匹配器 `KeywordMatcher`（单元）
| 用例 | 输入 | 预期 |
|------|------|------|
| KW-MAT-01 精确命中 | 文本含"抽烟" | 命中 KW_SMOKING，`matched_terms` 含"抽烟" |
| KW-MAT-02 正则命中 | 匹配 `patterns` 的文本 | 命中对应规则，`matched_terms` 含正则 group(0) |
| KW-MAT-03 多命中排序 | 文本同时含高低优先级关键词（如过敏+抽烟） | 返回列表按 `priority` 降序（KW_ALLERGY=200 在前） |
| KW-MAT-04 未命中 | 无关文本 | 返回空列表 `[]` |
| KW-MAT-05 空输入 | `None` / `""` | 返回空列表，不抛异常 |
| KW-MAT-06 进程缓存 | 连续两次 `match()` | 仅首次查库（`load_rules` 缓存生效）；`force=True` 才重载 |
| KW-MAT-07 仅加载生效规则 | 库中存在 `status!='active'` 或 `deleted=1` 的规则 | 不参与匹配 |
| KW-MAT-08 坏正则容错 | 规则含非法正则 | 加载时告警跳过该 pattern，其余规则正常 |
| KW-MAT-09 约束提示 | 命中含 `action_payload.prompt` 的规则 | `MatchResult.constraint_prompt` 返回该 prompt；无 prompt 时为空串 |

### 2.3 拦截链路（集成，见 3.2 send_message）
- 命中关键词时 `SendMessageResponse.intercepted=True`，且额外发布一条 `ConstraintEvent`。
- 未命中时 `intercepted=False`，不发布 `ConstraintEvent`。
- 拦截日志包含命中的 `rule_code` 列表。

## 四、步骤8：SSE 流式推送

### 4.1 消息格式化 `sse_service`（单元）
| 用例 | 输入 | 预期 |
|------|------|------|
| SSE-FMT-01 事件名映射 | EventType 各值 | 正确映射为 `dialog_message`/`progress_update`/`error` |
| SSE-FMT-02 字段解码 | Redis bytes 字段 | bytes 解码为 str；以 `[`/`{` 开头的值 JSON 解析为对象 |
| SSE-FMT-03 输出结构 | `format_sse_event(msg_id, fields)` | 返回含 `event`/`id`/`data`（data 为 JSON 串） |
| SSE-FMT-04 stream key | `dialog_stream_key(session_no)` | 返回 `dialog_stream:{session_no}` |

### 4.2 事件流生成 `stream_dialog_events`（集成，fake/real Redis）
| 用例 | 步骤 | 预期 |
|------|------|------|
| SSE-STR-01 实时推送 | 订阅后向 stream `xadd` 一条事件 | 消费端收到对应 SSE 事件，`id` 为消息 ID |
| SSE-STR-02 起点 `$` | 无 Last-Event-ID | 只收订阅后的新消息，不回放历史 |
| SSE-STR-03 断线续读 | 带 `Last-Event-ID` 重连 | 从该 ID 之后续读，不丢消息、不重复 |
| SSE-STR-04 心跳 | 空闲超过 30 秒 | 产出 ping（`ping=HEARTBEAT_INTERVAL`） |
| SSE-STR-05 客户端断开 | 消费端取消 | 捕获 CancelledError，协程干净退出 |
| SSE-STR-06 last_id 递进 | 连续多条消息 | 每条后 last_id 更新为该消息 ID |

### 4.3 SSE 路由（集成）
| 用例 | 步骤 | 预期 |
|------|------|------|
| SSE-API-01 患者端订阅 | `GET /api/sse/dialog/{session_no}`（会话存在） | 200，`Content-Type: text/event-stream` |
| SSE-API-02 会话不存在 | 不存在 session_no | `code=ERR_SSE_001`，HTTP 404 |
| SSE-API-03 医护端只读监听 | `GET /api/sse/monitor/{session_no}` | 200，收到与患者端同一 `dialog_stream` 的事件 |
| SSE-API-04 多客户端并订 | 患者端 + 医护端同时订阅同会话 | 两端均收到同一事件，无冲突 |

## 五、E2E 闭环（需 Celery + Redis + DB）

| 用例 | 场景 | 预期 |
|------|------|------|
| E2E-01 全链路 | 创建任务 → 开始对话 → 订阅 SSE → 发消息 | SSE 端依次收到 Agent 异步产出的回复事件 |
| E2E-02 拦截闭环 | 发含"过敏"消息 | 收到约束事件驱动的下一轮约束提示 |
| E2E-03 断线恢复 | E2E-01 中途断开 SSE 后带 Last-Event-ID 重连 | 补齐断线期间的事件，无丢失 |

## 六、验收口径

- **步骤7**：关键词精确/正则匹配准确；多命中按 `priority` 降序；导入幂等；命中触发约束提示注入。
- **步骤8**：事件实时到达且连接稳定；带 `Last-Event-ID` 重连不丢消息；患者端/医护端并订无冲突；空闲 30 秒有心跳。
- **步骤9**：应用正常启动、`/docs` 可访问；任务创建 → 开始对话 → 发消息全链路正确；同会话并发锁生效；错误场景返回统一错误码与友好提示。
