# 桌面对话进度与候选题冷却审查

日期：2026-09-03。基线提交：`7a84d7f`。功能分支：`feat/dialog-question-progress`。

## 实现结果

- 共享服务按任务绑定量表、有效答案、患者消息与 `question_turn` 事件计算三种题目状态。
  候选最多三道；实际问过的题冷却两轮；普通回应允许空选择，澄清保留当前题关联。
- 文字首问和后续回复、实时语音均接入内部选题工具。只有合法报告后才放行患者可见增量；
  冷却中的题不可作为新题选择，但允许继续解释当前题。
- 选题记录基于完整回复与固定来源消息幂等写入；来源语音转写晚到、重试、页面刷新和
  文字/语音切换共享同一历史，候选展示及中间工具响应不计提问。
- 桌面患者对话左侧按量表显示全部题目、三种状态及当前题，顶部和侧栏共用记录进度。
  首次加载、消息/抽取更新、十五秒轮询刷新，失败标注旧快照；手机保持原布局。

## 审查修复

1. 修复历史无题目关联导致文本 Runner 崩溃；无关联保持为空，不猜第一题。
2. 修复 AI 消息已保存而题目事件失败的窗口；重试先补事件再发布完成快照。
3. 保存和 SSE 使用实际选择 ID，避免旧 Redis 计划与数据库题目不一致导致关联丢失。
4. 首问同样使用候选和空选择协议，不再固定旧计划第一题。
5. 同轮非法更换选择关闭输出门禁；保留首次确认选择用于纠正，避免另一道题漏出。
6. 语音非法选题后继续有上限的工具纠正；失败不抛异常退出整条上游消费。
7. `failed/incomplete/cancelled` 及已被打断的迟到响应不记录已问。
8. 取消清除该响应的待续工具并废弃其选择；旧响应迟到工具不能选择新轮题目。
9. 修复桌面对话额外 34px 页面滚动与上下进度数值不一致。实际浏览器证据见
   `桌面对话进度浏览器验证.md` 与同目录截图。
