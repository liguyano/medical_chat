# 本地启动说明（Windows PowerShell）

本文用于 Windows 本地开发联调。建议按下面的顺序打开多个 PowerShell 窗口，
每个长期运行的服务都保持在自己的窗口中。

## 一、启动前提

- Docker Desktop 已启动，并使用 Linux containers。
- 后端已安装 `uv`，前端已安装 Node.js 和 `pnpm`。
- 第一次运行时，先完成依赖安装和配置文件初始化。
- 项目目录为 `E:\codes\medical-evaluate`。

## 二、启动 PostgreSQL 和 Redis

Docker 只负责启动后端依赖的 PostgreSQL 和 Redis，不需要进入 Docker 容器操作。

在任意 PowerShell 窗口执行：

```powershell
Set-Location E:\codes\medical-evaluate
docker compose up -d postgres redis
docker compose ps
```

看到 `medical-evaluate-postgres` 和 `medical_redis` 状态为 `Up` 或 `running`，
说明数据库和 Redis 已启动。

## 三、第一次启动后端前的准备

在项目根目录执行一次：

```powershell
Set-Location E:\codes\medical-evaluate
Copy-Item config.example.yaml config.yaml
$env:DASHSCOPE_API_KEY="你的模型 API Key"
```

如果已经存在 `config.yaml`，不要重复覆盖。模型 API Key 也可以直接写入本地
配置文件，具体以项目配置为准。

## 四、安装后端依赖和初始化数据库

第一次运行，或 `backend` 依赖发生变化时执行：

```powershell
Set-Location E:\codes\medical-evaluate\backend
uv sync
uv run alembic upgrade head
```

本地需要演示账号、患者和量表数据时，再执行：

```powershell
uv run python -m app.commands.seed_demo
```

`seed_demo` 仅用于本地联调，生产环境禁止执行。

## 五、启动后端 API

打开一个新的 PowerShell 窗口：

```powershell
Set-Location E:\codes\medical-evaluate\backend
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

看到 `Application startup complete` 和 `Uvicorn running on ...:8000`，说明 API 已启动。

健康检查：

```powershell
Invoke-WebRequest http://127.0.0.1:8000/health
```

## 六、启动 Celery Worker 和 Beat（后端异步任务）

Celery 不是前端。它负责后台执行 Schedule Agent、Dialog Agent、字段抽取和护理
计划等耗时任务。要完整运行 AI 对话流程，需要启动 Worker 和 Beat。

最简单的 Windows 启动方式是启动一个 Worker，它会消费项目的全部队列。打开新的
PowerShell 窗口：

```powershell
Set-Location E:\codes\medical-evaluate\backend
uv run python -m app.celery_app.worker
```

再打开一个新的 PowerShell 窗口启动定时补偿任务：

```powershell
Set-Location E:\codes\medical-evaluate\backend
uv run python -m app.celery_app.beat
```

只打开页面或进行不依赖异步任务的基础浏览时，可以暂时不启动这两个进程；创建
AI 对话任务、生成首问、处理患者回答和生成护理计划时必须启动。

## 七、启动前端

第一次运行，或前端依赖发生变化时，在新的 PowerShell 窗口执行：

```powershell
Set-Location E:\codes\medical-evaluate\frontend
pnpm install
```

确认 `frontend\.env.local` 使用后端 API 联调配置：

```dotenv
NEXT_PUBLIC_DATA_MODE=api
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
NEXT_PUBLIC_DIALOG_TRANSPORT=websocket
NEXT_PUBLIC_API_TIMEOUT_MS=15000
```

启动前端开发服务器：

```powershell
Set-Location E:\codes\medical-evaluate\frontend
pnpm dev
```

浏览器访问：

- 医护端：http://localhost:3000/nurse
- 患者端：http://localhost:3000/patient

## 八、每天的推荐启动顺序

1. 启动 Docker Desktop。
2. 在项目根目录执行 `docker compose up -d postgres redis`。
3. 在 `backend` 窗口启动 API。
4. 在另一个 `backend` 窗口启动 Worker。
5. 在另一个 `backend` 窗口启动 Beat。
6. 在 `frontend` 窗口执行 `pnpm dev`。
7. 打开 `http://localhost:3000/nurse` 或 `http://localhost:3000/patient`。

## 九、停止服务

在 API、Worker、Beat、前端各自的 PowerShell 窗口按 `Ctrl+C`。

停止 Docker 中的 PostgreSQL 和 Redis：

```powershell
Set-Location E:\codes\medical-evaluate
docker compose stop postgres redis
```

只停止容器不会删除数据库数据卷。不要使用 `docker compose down -v`，除非明确要
删除本地数据库和 Redis 数据。

## 十、常见现象

- `docker compose ...` 无法连接 `docker_engine`：先启动 Docker Desktop。
- `uv` 找不到：说明 `uv` 未安装或当前 PowerShell 尚未刷新 PATH；重新打开 PowerShell
  后检查 `uv --version`。
- 前端页面打不开：确认 `pnpm dev` 窗口显示 `Ready`，访问端口为 3000。
- AI 任务一直 pending：确认 Worker 和 Beat 都在运行，并且窗口没有报错。
- 修改 `config.yaml` 或后端代码后：重启 API；修改 Worker 相关代码后同时重启 Worker。
